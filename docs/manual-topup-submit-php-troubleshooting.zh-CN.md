# 个人收款码充值跳到 `submit.php` 的原因与配置说明

## 1. 现象

点击钱包页里的“支付宝充值”或“微信充值”后，浏览器打开了类似下面的地址：

- `http://localhost:5174/submit.php`

并提示网页无法访问。

## 2. 原因

这不是“个人收款码人工充值”流程，而是旧的“易支付 / epay 在线支付”流程。

当前代码里有两套不同的充值方式：

- 易支付在线充值
  - 前端点击后会调用 `/api/user/pay`
  - 后端会把表单提交到支付网关返回的 `submit.php`
- 个人收款码人工充值
  - 前端点击后会调用 `/api/user/manual/pay`
  - 只会创建待审核订单，不会跳转新标签页

也就是说，只要你点击的是旧的 `alipay` / `wxpay` 支付按钮，就会继续走 `submit.php`。

## 3. 为什么会打开 `http://localhost:5174/submit.php`

这说明当前后台里的 `PayAddress` 大概率被配置成了前端开发地址：

- `http://localhost:5174`

但 `PayAddress` 本来应该填写：

- 真实的易支付网关地址

如果你根本不用易支付，而是只想用个人支付宝收款码、个人微信收款码，那么这里不应该继续保留这套配置。

## 4. 个人收款码正确配置方式

后台路径：

- `系统设置 -> 支付设置 -> 支付设置`

需要配置这些项目：

- `启用个人收款码人工充值` = 开启
- `支付宝个人收款码图片地址` = 可公开访问的图片 URL
- `微信个人收款码图片地址` = 可公开访问的图片 URL
- `支付宝固定金额收款码配置` = 可选，按实付金额配置固定金额收款码
- `微信固定金额收款码配置` = 可选，按实付金额配置固定金额收款码
- `人工充值说明` = 例如“付款时请备注订单号，付款后等待管理员审核”

固定金额收款码配置示例：

```json
{
  "20": "https://example.com/alipay-20.png",
  "50": "https://example.com/alipay-50.png",
  "100.00": "https://example.com/alipay-100.png"
}
```

如果用户选择的实付金额命中了固定金额收款码，前端会优先弹出对应二维码。没有命中时，会退回通用个人收款码。

用户侧正确使用方式：

- 在钱包页选择充值额度
- 点击“支付宝充值”或“微信充值”
- 系统先生成待审核订单，并弹出对应收款二维码
- 用户扫码付款
- 付款备注中填写弹窗里的订单号
- 管理员到账后手动补单

这个流程不会打开 `submit.php`。

## 5. 如果你只想保留个人收款码

建议同时处理旧的易支付配置，避免混淆：

1. 清空 `PayAddress`
2. 清空 `EpayId`
3. 清空 `EpayKey`
4. 检查 `PayMethods`，删除 `alipay`、`wxpay`、`custom1` 等旧易支付方式

如果不清理，历史配置仍可能让页面继续出现旧的易支付支付入口。

## 6. 当前代码已做的处理

为避免误点，当前前端已调整为：

- 当“个人收款码人工充值”开启时
- 钱包页会自动隐藏旧的易支付按钮，例如 `alipay`、`wxpay`、`custom1`
- 在“选择支付方式”里显示“支付宝充值”和“微信充值”
- 点击后弹出对应二维码和订单号

因此，个人收款码场景下，钱包页不应再跳到 `submit.php`。

## 7. 是否需要重启程序

通常不需要重启。

支付设置保存成功后，刷新页面即可重新读取 `/api/user/topup/info` 配置。

但如果你当前运行的是前端开发环境，并且页面仍然显示旧按钮，可以按下面顺序检查：

1. 确认后台保存成功
2. 强制刷新浏览器
3. 确认当前前端已经是最新代码
4. 确认不是旧的构建产物或旧页面缓存

## 8. 最终判断标准

如果配置正确，个人收款码场景应该表现为：

- 页面展示“个人收款码人工充值”
- “选择支付方式”里有“支付宝充值”或“微信充值”
- 点击后弹出对应二维码，并显示订单号
- 不会打开任何 `submit.php`

如果仍然打开 `submit.php`，说明当前点击到的仍不是人工充值入口，而是旧的易支付入口，或者前端代码还没有更新到最新版本。

## 9. 为什么个人收款码不能自动带金额

普通个人支付宝/微信“收款码”通常是静态码，本质上只是一个收款入口，并不包含当前订单金额、订单号、回调地址。

因此：

- 使用通用个人收款码时，用户通常需要手动输入金额
- 系统也不能通过支付宝/微信回调自动确认到账
- 必须由管理员根据订单号和实际到账记录手动补单

如果要做到“扫码后自动显示金额、支付成功自动回调入账”，需要接入支付宝/微信官方商户支付能力，而不是普通个人静态收款码。

折中方案是使用固定金额收款码：

- 在支付宝/微信里分别生成 20 元、50 元、100 元等固定金额收款码
- 后台把这些固定金额码配置到对应 JSON 中
- 用户选择对应金额时，前端弹出固定金额码

这个方案可以减少用户手动输入金额，但仍然没有官方支付回调，管理员仍需审核到账。
