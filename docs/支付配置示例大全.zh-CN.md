## 2. 先记住：哪些字段本来就是 JSON

当前项目里，最常需要你手写 JSON 的字段主要有这些：

- `PayMethods`
- `TopupGroupRatio`
- `AmountOptions`
- `AmountDiscount`
- `ManualTopUpAlipayAmountQRCodes`
- `ManualTopUpWeChatAmountQRCodes`

而这些字段不是 JSON，而是普通字符串或开关：

- `ServerAddress`
- `PayAddress`
- `EpayId`
- `EpayKey`
- `CustomCallbackAddress`
- `AlipayOfficialAppId`
- `AlipayOfficialPrivateKey`
- `AlipayOfficialPublicKey`
- `WeChatPayOfficialAppId`
- `WeChatPayOfficialMchId`
- `WeChatPayOfficialSerialNo`
- `WeChatPayOfficialPrivateKey`
- `WeChatPayOfficialAPIv3Key`
- `WeChatPayOfficialPlatformCert`

## 3. 先给你一组通用基础示例

这组值不代表你一定要照抄，而是让你明白字段长什么样。

### 3.1 基础地址示例

```json
{
  "ServerAddress": "https://pay.example.com",
  "CustomCallbackAddress": "https://api.example.com"
}
```

说明：

- `ServerAddress` 是你正式站点地址
- `CustomCallbackAddress` 只有在你想把回调单独走另一个 API 域名时才填
- 如果你没有单独 API 域名，可以不填 `CustomCallbackAddress`

### 3.2 充值档位示例

```json
[10, 20, 50, 100, 200, 500]
```

可直接用于：

- `AmountOptions`

### 3.3 充值折扣示例

```json
{
  "100": 0.98,
  "200": 0.95,
  "500": 0.9
}
```

可直接用于：

- `AmountDiscount`

含义示例：

- 充 `100`，按 `0.98` 折计算
- 充 `500`，按 `0.9` 折计算

### 3.4 用户组充值倍率示例

```json
{
  "default": 1,
  "vip": 1.05,
  "svip": 1.1
}
```

可直接用于：

- `TopupGroupRatio`

## 4. 场景一：只使用 `ZPAY` / `epay` 聚合支付

这是最接近你之前 `ikuncode` 链路的场景。

### 4.1 适合谁

- 你想尽快上线
- 你已经接了 `ZPAY`
- 你还不想切官方直连

### 4.2 建议配置示例

```json
{
  "ServerAddress": "https://pay.example.com",
  "CustomCallbackAddress": "https://api.example.com",
  "PayAddress": "https://zpayz.cn",
  "EpayId": "2025082723051531",
  "EpayKey": "your_epay_sign_key",
  "Price": "7.3",
  "MinTopUp": "1"
}
```

### 4.3 `PayMethods` 示例

```json
[
  {
    "name": "支付宝",
    "type": "alipay",
    "color": "rgba(var(--semi-blue-5), 1)"
  },
  {
    "name": "微信",
    "type": "wxpay",
    "color": "rgba(var(--semi-green-5), 1)"
  }
]
```

### 4.4 这套配置的效果

- 钱包页显示旧在线支付按钮
- 前端点击后会请求 `/api/user/pay`
- 浏览器会自动表单跳转第三方网关
- 回调走 `/api/user/epay/notify`

### 4.5 最常见误区

- `PayAddress` 填成 `https://zpayz.cn/submit.php`
- `PayAddress` 填成你自己前端地址
- 把 `EpayId` 填成支付宝 `AppId`

## 5. 场景二：只使用支付宝 / 微信官方直连

### 5.1 适合谁

- 你已经拿到官方商户参数
- 你想让支付链路更可控
- 你准备把 `ZPAY` 当过渡方案或彻底下线

### 5.2 官方配置示例

注意：下面是“结构示例”，不是真实密钥。

```json
{
  "ServerAddress": "https://pay.example.com",
  "Price": "7.3",
  "MinTopUp": "1",
  "AlipayOfficialEnabled": "true",
  "AlipayOfficialAppId": "2021000000000000",
  "AlipayOfficialGateway": "https://openapi.alipay.com/gateway.do",
  "AlipayOfficialPrivateKey": "-----BEGIN PRIVATE KEY-----\\n你的支付宝应用私钥\\n-----END PRIVATE KEY-----",
  "AlipayOfficialPublicKey": "-----BEGIN PUBLIC KEY-----\\n你的支付宝公钥\\n-----END PUBLIC KEY-----",
  "WeChatPayOfficialEnabled": "true",
  "WeChatPayOfficialAppId": "wx1234567890abcdef",
  "WeChatPayOfficialMchId": "1900001234",
  "WeChatPayOfficialSerialNo": "5A1B2C3D4E5F67890123456789ABCDEF12345678",
  "WeChatPayOfficialPrivateKey": "-----BEGIN PRIVATE KEY-----\\n你的微信商户私钥\\n-----END PRIVATE KEY-----",
  "WeChatPayOfficialAPIv3Key": "12345678901234567890123456789012",
  "WeChatPayOfficialPlatformCert": "-----BEGIN CERTIFICATE-----\\n你的微信平台证书\\n-----END CERTIFICATE-----"
}
```

### 5.3 这时 `PayMethods` 要不要填官方方式

不需要。

原因是：

- 当前项目会在后端根据能力自动追加官方支付方式
- 支付宝官方对应 `alipay_official`
- 微信官方对应 `wxpay_native`

也就是说，官方入口不是靠你在 `PayMethods` 里手写出来的。

### 5.4 这套配置的效果

- 钱包页会出现官方支付宝、官方微信入口
- 点击后会请求：
  - `/api/user/alipay/pay`
  - `/api/user/wechat/pay`
- 前端显示二维码弹窗
- 回调分别走：
  - `/api/alipay/notify`
  - `/api/wechatpay/notify`

### 5.5 建议的 `PayMethods`

如果你完全不再使用旧 `epay`，建议清空旧值或去掉 `alipay` / `wxpay`。

可以用最小化示例：

```json
[]
```

或者保留其他非 `epay` 的自定义配置，但不要继续保留旧在线支付入口。

  "AlipayOfficialAppId": "2021000000000000",
  "AlipayOfficialGateway": "https://openapi.alipay.com/gateway.do",
  "AlipayOfficialPrivateKey": "-----BEGIN PRIVATE KEY-----\\n你的支付宝应用私钥\\n-----END PRIVATE KEY-----",
  "AlipayOfficialPublicKey": "-----BEGIN PUBLIC KEY-----\\n你的支付宝公钥\\n-----END PUBLIC KEY-----",
  "WeChatPayOfficialEnabled": "true",
  "WeChatPayOfficialAppId": "wx1234567890abcdef",
  "WeChatPayOfficialMchId": "1900001234",
  "WeChatPayOfficialSerialNo": "5A1B2C3D4E5F67890123456789ABCDEF12345678",
  "WeChatPayOfficialPrivateKey": "-----BEGIN PRIVATE KEY-----\\n你的微信商户私钥\\n-----END PRIVATE KEY-----",

## 10. 通过接口保存配置时，可参考这种 JSON 结构

后台页面实际上是逐条调用 `/api/option/` 保存的。

如果你想自己整理批量配置，可以先按这种结构准备：

```json
[
  { "key": "ServerAddress", "value": "https://pay.example.com" },
  { "key": "PayAddress", "value": "https://zpayz.cn" },
  { "key": "EpayId", "value": "2025082723051531" },
  { "key": "EpayKey", "value": "your_epay_sign_key" },
  { "key": "Price", "value": "7.3" },
  { "key": "MinTopUp", "value": "1" },
  {
    "key": "PayMethods",
    "value": "[{\"name\":\"支付宝\",\"type\":\"alipay\",\"color\":\"rgba(var(--semi-blue-5), 1)\"},{\"name\":\"微信\",\"type\":\"wxpay\",\"color\":\"rgba(var(--semi-green-5), 1)\"}]"
  },
  {
    "key": "payment_setting.amount_options",
    "value": "[10,20,50,100,200,500]"
  },
  {
    "key": "payment_setting.amount_discount",
    "value": "{\"100\":0.98,\"200\":0.95,\"500\":0.9}"
  }
]
```

注意：

- 这是“整理示例”
- 不代表当前后台有现成的批量导入界面
- 但很适合你自己做迁移清单或脚本模板

## 11. 上线前最推荐的一组“稳妥模板”

如果你现在处于从 `ZPAY` 迁移到官方直连的阶段，我最推荐你先用这一套思路：

### 11.1 先保留旧通道

```json
{
  "PayAddress": "https://zpayz.cn",
  "EpayId": "你的旧商户ID",
  "EpayKey": "你的旧商户密钥"
}
```

### 11.2 再补官方参数

```json
{
  "AlipayOfficialEnabled": "true",
  "WeChatPayOfficialEnabled": "true"
}
```

前提是所有官方参数已经填全。

### 11.3 再把旧入口改成“备用命名”

```json
[
  {
    "name": "支付宝（备用）",
    "type": "alipay",
    "color": "rgba(var(--semi-blue-5), 1)"
  },
  {
    "name": "微信（备用）",
    "type": "wxpay",
    "color": "rgba(var(--semi-green-5), 1)"
  }
]
```

这样做的好处是：

- 业务不中断
- 你能看出哪个是旧通道
- 出问题能快速回退

## 12. 最容易照抄出错的地方

### 12.1 不要把示例密钥当真实值

文档里的：

- `your_epay_sign_key`
- `你的支付宝应用私钥`
- `你的微信商户私钥`

都只是占位符。

### 12.2 多行 PEM 内容复制时不要丢头尾

比如：

- `-----BEGIN PRIVATE KEY-----`
- `-----END PRIVATE KEY-----`

这些都必须完整。

### 12.3 官方支付方式不要手写进 `PayMethods`

当前项目里：

- 官方支付方式是后端自动追加的
- 不是靠你在 `PayMethods` 里塞 `alipay_official` / `wxpay_native`

### 12.4 人工充值模式下不要继续保留旧 `alipay` / `wxpay`

否则用户还是会误点旧在线支付入口。

---

## 13. 一句话建议

如果你现在最需要的是“拿着模板直接填”，最稳的做法是：

> 先按“官方直连 + `ZPAY` 并行”模板上线，等真实支付和真实回调稳定后，再慢慢删掉旧 `epay` 配置。
