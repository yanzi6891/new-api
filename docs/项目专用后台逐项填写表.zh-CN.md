# `new-api` 项目专用后台逐项填写表

更新时间：2026-04-20

## 1. 这份表怎么用

这份文档不是讲原理，而是给你直接照着填后台用的。

适合你当前这条推荐落地路线：

- 支付宝官方直连：主链路
- 微信官方直连：主链路
- `ZPAY` / `epay`：迁移期备用链路
- 人工充值：可选兜底，不建议做主入口

你可以把这份表当成：

- 后台填写作业单
- 配置交接单
- 上线前逐项核对表

建议配合这几份文档一起看：

- `docs/项目专用最终支付配置清单.zh-CN.md`
- `docs/支付后台字段级填写对照表.zh-CN.md`
- `docs/支付配置示例大全.zh-CN.md`
- `docs/支付联调排错手册.zh-CN.md`

## 2. 建议填写顺序

不要想到什么填什么，建议严格按下面顺序：

1. 先填通用基础项
2. 再填支付宝官方参数
3. 再填微信官方参数
4. 再保留并核对 `ZPAY` 备用参数
5. 最后再决定是否开启人工充值
6. 最后才调整 `PayMethods`、档位、折扣等展示型配置

原因很简单：

- `ServerAddress` 不对，回调大概率就不对
- 官方参数不齐，开关开不起来
- 旧 `ZPAY` 删太早，出问题没法回退

## 10. 最终填写后的“目标状态确认表”

如果你按推荐方案填写完成，那么最终应满足下面这些状态：

### 支付能力状态

- [ ] 钱包页显示支付宝官方入口
- [ ] 钱包页显示微信官方入口
- [ ] 钱包页如保留旧入口，名称明确带“备用”
- [ ] 人工充值如开启，只是补充入口

### 下单接口状态

- [ ] 支付宝官方走 `/api/user/alipay/pay`
- [ ] 微信官方走 `/api/user/wechat/pay`
- [ ] 旧 `ZPAY` 备用仍可走 `/api/user/pay`
- [ ] 人工充值如开启，走 `/api/user/manual/pay`

### 回调与状态查询

- [ ] 支付宝回调：`/api/alipay/notify`
- [ ] 微信回调：`/api/wechatpay/notify`
- [ ] `ZPAY` 回调：`/api/user/epay/notify`
- [ ] 官方订单状态轮询：`/api/user/topup/status/:tradeNo`
