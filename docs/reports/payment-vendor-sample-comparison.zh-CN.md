# 主流支付平台样例评估表

> 更新日期：2026-04-20  
> 说明：这是基于官方公开资料整理的一版“已填样例”，方便你把上一份模板快速落地。  
> 重要提醒：以下 `费率`、`账期`、`保证金`、`拒付费用`、`是否支持某类业务`，很多都和主体注册地、行业类目、月交易额、风控评级强相关。尤其中国大陆平台与企业级 PSP 的正式商务条款，公开信息通常不完整，所以文中会明确标注 `需商务确认`。  
> 推断说明：文中的“更适合谁”“更适合什么场景”属于基于官方产品定位、公开文档、支付能力范围做出的选型推断，不是平台官方自述排名。

## 1. 选取的 6 个样例平台

这份样例先填最常被放在同一张对比表里的 6 类平台：

- `Stripe`：国际 API-first 全栈 PSP
- `Adyen`：国际企业级全渠道 PSP
- `支付宝开放平台 / 服务商生态`：中国大陆官方直连生态
- `微信支付 / 合作伙伴生态`：中国大陆官方直连生态
- `收钱吧`：中国大陆门店型聚合收单
- `汇付天下`：中国大陆平台型支付与清结算方案

## 2. 一页结论

- 如果你做 `中国大陆在线充值站`，优先顺序通常是：`微信支付 + 支付宝`，再看是否需要 `汇付天下` 或旧聚合通道做过渡。
- 如果你做 `出海 SaaS / API 平台 / 海外开发者收款`，优先顺序通常是：`Stripe`，大型企业再看 `Adyen`。
- 如果你做 `中国大陆线下门店 / 餐饮零售`，优先顺序通常是：`收钱吧`，其次再看 `支付宝/微信` 官方生态深接入。
- 如果你做 `平台分账 / 清结算 / 代发`，中国大陆更值得看 `汇付天下`，国际更值得看 `Stripe Connect` 或 `Adyen for Platforms`。

## 4. 费率、账期、开通门槛样例

> 本节故意不写“伪精确”的统一费率数字。  
> 原因是：除了少数国际平台会公开标准价，大多数中国大陆平台和企业级平台都需要按主体、行业、交易额、地区、风控等级单独报价。

| 平台 | 标准定价公开程度 | 账期公开程度 | 开通门槛样例 | 适合主体 | 样例判断 |
| --- | --- | --- | --- | --- | --- |
| Stripe | 高：官网有 Pricing 页面，很多基础费用公开 | 中到高：可公开了解基础收款逻辑，但最终受国家/账户影响 | 对开发者友好，文档和 API 自助能力强；但主体地区和业务类目必须匹配 | 海外主体、出海主体、SaaS、电商、开发者平台 | 最适合作为国际默认主网关 |
| Adyen | 中：有 Pricing 页面，但企业级方案通常需销售报价 | 中：企业级账期通常需合同确认 | 偏中大客户和企业项目，接入和商务门槛高于 Stripe | 大型品牌、零售、平台型企业 | 更适合企业级和全渠道统一场景 |
| 支付宝开放平台 | 低到中：公开的是产品与接入文档，标准费率通常要按产品和商户类目确认 | 低到中：以签约与商户方案为准 | 需本地商户资质、应用/商户开通、证书密钥等 | 中国大陆公司、服务商、线下门店、线上业务 | 适合中国大陆本地业务主链路之一 |
| 微信支付 | 低到中：公开的是产品与接入文档，正式费率通常要按类目和模式确认 | 低到中：以商户协议和合作模式为准 | 需商户号、证书、APIv3 Key、平台证书等；对商户资质要求明确 | 中国大陆公司、服务商、公众号/小程序业务 | 适合中国大陆本地业务主链路之一 |
| 收钱吧 | 低：更多是销售方案与线下服务方案 | 低：账期和结算要看合同与行业方案 | 对门店和线下经营支持强，但通常走销售/服务落地 | 小微门店、连锁门店、本地生活商户 | 强在线下门店，不是全球 API 默认首选 |
| 汇付天下 | 低：更多是解决方案型商务报价 | 低：账期、清结算、保证金常需项目级确认 | 偏企业级和平台级需求，商务和风控评估一般比纯扫码收款重 | 平台业务、复杂分账、行业支付场景 | 适合复杂账务和平台资金流 |

### 4.1 关于费率公开性的一个现实判断

- `Stripe` 的公开定价透明度最高，适合快速预估初期成本。
- `Adyen` 虽有公开 pricing 说明，但真实价格更偏企业级定制。
- `支付宝`、`微信支付`、`收钱吧`、`汇付天下` 的正式费率和账期，通常必须进入商务流程后才能拿到准确结果。

如果你的目标是“先快速做预算”，通常可以：

1. 用 `Stripe` 的公开价格估算国际部分  
2. 用国内平台的 `需商务确认` 标记预留一个更宽的支付成本区间  
3. 在正式签约前，不把国内渠道写死到财务模型里

## 6. 如果你的项目是 `new-api` 这类 AI / API 充值平台

### 6.1 中国大陆用户为主

推荐优先级：

1. `微信支付`
2. `支付宝开放平台`
3. `汇付天下` 或兼容型聚合方案
4. `人工充值` 兜底

原因：

- 用户习惯最强
- 回调链路明确
- 与本地钱包一致
- 对 API 充值型业务更容易解释支付场景

### 6.2 海外用户为主

推荐优先级：

1. `Stripe`
2. `Adyen`（偏大客户或企业级）
3. 视地区和支付方式缺口再找补充通道

原因：

- 文档成熟
- 对订阅、API 充值、Webhook、平台能力支持更完整
- 更适合开发者产品和国际支付链路

### 6.3 混合用户结构

推荐组合：

- 中国大陆：`微信支付 + 支付宝`
- 海外：`Stripe`
- 如需复杂平台账务：中国大陆补 `汇付天下`

## 7. 样例淘汰/保留建议

| 平台 | 对 `new-api` 的建议结论 | 理由 |
| --- | --- | --- |
| Stripe | 主选保留 | 国际 API / 订阅 / 充值能力最适合当前产品形态 |
| Adyen | 备选保留 | 强，但通常更适合规模更大或全渠道企业 |
| 支付宝开放平台 | 主选保留 | 中国大陆核心支付方式之一 |
| 微信支付 | 主选保留 | 中国大陆核心支付方式之一 |
| 收钱吧 | 场景性保留 | 如果做门店充值、线下场景才值得重点考虑 |
| 汇付天下 | 备选保留 | 如果后续做分账、平台账务、行业支付，会很有价值 |

## 8. 商务沟通时建议优先问的 12 个问题

1. 是否接受 `API 充值`、`余额充值`、`点数充值`、`credits` 这类业务  
2. 是否允许销售第三方服务额度或代充值  
3. 是否支持你当前主体注册地  
4. 账期是 `T+1`、`T+7`、周结还是月结  
5. 是否有保证金、滚动保留金、负余额机制  
6. 退款怎么计费，拒付怎么计费  
7. 是否支持订阅、自动续费、失败重试  
8. 是否支持 webhook 重试、查单、幂等  
9. 是否支持子商户、平台抽佣、分账、代发  
10. 风控拦截后是否有人能人工处理  
11. 是否支持测试环境、联调环境、正式环境隔离  
12. 上线后账号被限时的 SLA 是多少

## 9. 为什么这份样例没有把“精确费率”全部填满

我明确说明一下原因：

- `Stripe`：公开价格相对透明，可以做预算基线
- `Adyen`：公开定价逻辑有，但真实价格常取决于企业谈判
- `支付宝`、`微信支付`：公开重点是产品能力和接入说明，不是统一价目表
- `收钱吧`、`汇付天下`：更偏解决方案和销售报价，公开价目表通常不完整

因此，如果要做真正的决策表，最合理的做法是：

- 样例阶段先按 `公开透明度 + 商务门槛 + 场景匹配度` 做第一轮筛选
- 第二轮再让销售给出正式报价单和账期条款
