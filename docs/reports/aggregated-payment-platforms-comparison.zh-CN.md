# 国内及国际主流聚合支付平台分类对比

> 更新日期：2026-04-19  
> 适用对象：准备做中国大陆收款、跨境收款、SaaS 订阅、平台分账或全球多支付方式接入的产品/技术/运营团队  
> 说明：本文中的“主流”不是严格市场份额排名，而是结合 2026-04-19 可公开核实的官方产品资料、企业选型讨论中的高频出现度、支付方式覆盖、生态成熟度与持续运营情况筛选出的代表性平台。

## 1. 先说结论

- 如果你的核心场景是中国大陆线下门店、餐饮零售、到店经营，优先看 `收钱吧`、`拉卡拉`、`银联商务/云闪付生态`，其次再看是否需要 `支付宝/微信支付` 官方直连。
- 如果你的核心场景是中国大陆线上业务，但又想统一接入多个支付渠道、做分账、结算、代发或平台化能力，优先看 `汇付天下`、`Ping++`，并同步评估 `支付宝/微信支付` 服务商模式。
- 如果你的核心场景是跨境电商、海外 DTC、App 出海、全球收单，优先看 `Stripe`、`Adyen`、`Checkout.com`、`Airwallex`。
- 如果你的场景是大型全球品牌、全渠道零售、需要统一线上线下收单与风控，优先看 `Adyen`、`Worldpay`、`Checkout.com`。
- 如果你主要做新兴市场本地支付方式覆盖，如拉美、东南亚、中东、非洲，优先看 `dLocal`，其次再看 `Stripe`/`Adyen`/`Airwallex` 在目标国家的本地方法覆盖。
- 如果你是软件订阅、数字内容、SaaS 出海，而且不想自己处理全球税务、销售合规、部分拒付和主体责任，优先看 `Paddle`；如果你想保留更高控制权，则看 `Stripe Billing` 或 `Adyen`。

## 2. “聚合支付”到底指什么

“聚合支付”在国内和国际语境里其实不是一回事。

### 2.1 国内语境

国内通常把下面几类都笼统称为“聚合支付”：

- 聚合二维码/聚合收款码：一个码同时收 `支付宝`、`微信支付`、`云闪付` 等。
- 聚合收单服务商：提供收银台、POS、门店硬件、店员管理、账务对账、营销工具。
- 支付服务商/服务商模式：通过一个服务商后台帮助商户间接接入多个官方支付通道。

### 2.2 国际语境

国际市场更常见的叫法是：

- `PSP`（Payment Service Provider）：支付服务提供商，往往提供一个 API 接入卡支付、钱包、本地支付方式、退款、风控、订阅、分账、付款等。
- `Payment Gateway / Acquirer`：网关与收单能力。
- `Merchant of Record, MoR`：平台作为法定售卖主体处理税务、合规和收款责任，典型代表是 `Paddle`。

### 2.3 一个最重要的判断

不是所有“主流支付平台”都是真正意义上的“聚合平台”：

- `支付宝`、`微信支付`、`银联/云闪付` 更接近官方直连接入生态或服务商生态；
- `收钱吧`、`拉卡拉` 更像本土门店型聚合收单平台；
- `Stripe`、`Adyen`、`Checkout.com` 更像全球 API 型 PSP；
- `Paddle` 则不是纯 PSP，而是 `MoR` 模式。

所以企业选型时，应该先决定自己要的是：

1. 一个“码/一个 POS/一个后台”；
2. 一个“API/一个合同/统一结算”；
3. 一个“连税务和法定销售责任都外包”的方案。

## 3. 分类框架

| 类别 | 代表平台 | 本质定位 | 最适合的场景 |
| --- | --- | --- | --- |
| 中国大陆官方直连/服务商生态 | 支付宝、微信支付、银联商务/云闪付 | 官方支付通道与生态能力 | 深度使用本地钱包、公众号/小程序/生活号、线下扫码 |
| 中国大陆门店型聚合收单 | 收钱吧、拉卡拉、移卡（乐刷） | 门店收银、硬件、店员、营销、聚合码 | 餐饮、零售、本地生活、连锁门店 |
| 中国大陆开发者/平台型聚合 | 汇付天下、Ping++ | 统一 API、分账、清结算、平台化能力 | SaaS 平台、交易平台、线上业务、行业支付解决方案 |
| 国际全栈 PSP | Stripe、Adyen、Checkout.com、Worldpay、PayPal/Braintree | 全球收单、支付方式、风控、订阅、分账、付款 | 出海电商、SaaS、App、跨境品牌 |

| 国际 MoR | Paddle | 代管税务、合规、开票与部分支付责任 | SaaS、数字内容、软件订阅 |

## 4. 国内主流平台详细总结

> 说明：以下把中国大陆企业在实际选型里最常比较的“官方直连生态”和“第三方聚合服务商”放在一起说明，因为这几类平台通常会同时进入同一个评估清单。

| 平台 | 类型 | 主要能力 | 更适合谁 | 优势 | 劣势 |
| --- | --- | --- | --- | --- | --- |
| 支付宝开放平台 / 服务商生态 | 官方直连生态 | 当面付、App/网页支付、生活号/小程序生态、会员营销、退款对账 | 以支付宝流量和钱包支付为核心的线上/线下商户 | 用户覆盖大、官方能力深、生态工具多、品牌信任强 | 不是多通道聚合；如果还要接微信/银联，仍需额外对接或找服务商 |
| 微信支付 / 合作伙伴生态 | 官方直连生态 | Native/JSAPI/App/H5 支付、公众号/小程序闭环、服务商模式、品牌/门店方案 | 依赖微信生态获客和交易闭环的业务 | 小程序和社交闭环强、用户触达强、线下扫码成熟 | 同样不是多通道聚合；深度依赖微信生态；跨平台统一账务要另做整合 |
| 银联商务 / 云闪付生态 | 官方直连生态+收单网络 | 银联卡受理、扫码、POS、银行合作、行业解决方案 | 重视银行卡受理、线下终端、政府/国企/大型连锁 | 线下收单根基深、终端与银行网络强、合规稳健 | 产品和开发者体验通常不如新一代 API 型平台灵活，国际化能力相对有限 |
| 收钱吧 | 门店型聚合收单 | 聚合码、扫码点餐、收银系统、门店经营 SaaS、会员营销 | 中小商户、餐饮零售、本地生活门店 | 上线快、门店交付强、硬件和 SaaS 配套成熟、运营落地能力强 | 更偏线下门店；全球支付、复杂订阅、平台分账等能力不是强项 |
| 拉卡拉 | 门店型聚合收单 | 扫码收款、银行卡收单、POS、门店设备、商户服务 | 连锁门店、传统零售、需要终端设备和本地服务的商户 | 收单网络成熟、硬件覆盖强、商户触达广、执行稳 | 技术抽象层和开发者友好度通常不如纯 API 型平台；国际支付能力一般 |
| 汇付天下（含支付 PaaS / 斗拱等能力） | 开发者/平台型聚合 | 统一支付接入、清结算、分账、代发、行业支付方案 | 平台型业务、交易撮合、SaaS、行业支付 | 平台化和资金路由能力较强，适合做复杂账务与清结算 | 更偏 B 端解决方案，接入、商务和风控流程通常比门店型平台更重 |
| 移卡（乐刷） | 门店型聚合收单 | 商户收单、设备、店铺数字化、营销与增值服务 | 小微商户、线下门店、O2O 商家 | 中小商户覆盖广，支付与店铺数字化打包能力强 | 更偏本地商户经营；国际化、订阅和平台支付能力不算核心卖点 |
| Ping++ | 开发者型聚合 | 统一 API 接入多支付渠道、SDK、开发者接入 | 需要快速聚合多个支付通道的互联网团队 | 开发接入思路清晰、对工程团队友好、适合做统一支付层 | 相比超大规模官方生态和国际 PSP，线下服务网络、全球扩张能力和综合生态不占优 |

### 4.1 国内平台的本质差异

#### 官方直连型

- 核心优势：费率和链路更直接、能力更原生、营销和生态能力最深。
- 主要问题：要接多个支付方式时，合同、技术、对账、售后往往会变成多套体系。

#### 门店型聚合收单

- 核心优势：适合门店经营，交付速度快，通常自带收银、硬件、培训、巡店、店员管理。
- 主要问题：线上 API 能力、国际支付能力、订阅/平台分账等高级能力通常偏弱。

#### 开发者/平台型聚合

- 核心优势：更适合互联网产品、行业平台、SaaS、撮合交易和复杂账务。
- 主要问题：商务与风控门槛相对更高，实施周期通常长于纯聚合码产品。

## 5. 国际主流平台详细总结

| 平台 | 类型 | 主要能力 | 更适合谁 | 优势 | 劣势 |
| --- | --- | --- | --- | --- | --- |
| Stripe | 全球全栈 PSP | 卡支付、100+ 支付方式、订阅、Connect 分账、Radar 风控、开票 | 出海 SaaS、DTC、电商、开发者团队 | 文档和 API 体验强、产品线完整、上线效率高、生态成熟 | 成本不一定最低；大客户深度定制和复杂线下场景未必最佳；不同主体地区准入需单独确认 |
| Adyen | 全球企业级 PSP | 全球收单、本地支付方式、统一线上线下、风控、平台与市场方案 | 中大型品牌、全渠道零售、跨国企业 | 统一商务与数据链路强，线上线下整合能力突出，企业级稳定性高 | 更偏中大客户，接入和商务流程较重，自助化不如 Stripe |
| PayPal Enterprise / Braintree | 全球钱包+网关 | PayPal、Venmo（美国）、卡、Apple Pay、Google Pay、订阅与钱包支付 | 面向欧美消费市场、依赖 PayPal 转化的商户 | PayPal 品牌认知高、钱包转化好、Braintree 适合快速集成多钱包 | 纯卡收单和全渠道能力不一定优于顶级 PSP；不同产品线体验可能割裂 |
| Checkout.com | 全球 PSP | 统一支付 API、卡支付、本地支付方式、支付性能优化、全球收单 | 跨境电商、数字平台、中大型线上业务 | API 和性能口碑较好，全球卡收单和本地支付覆盖平衡 | 更偏中大型商户，产品自助化和生态广度通常不如 Stripe |
| Worldpay | 全球企业级收单/PSP | 大规模全球收单、卡支付、本地方法、线下终端、行业方案 | 超大商户、传统大型零售、全球线下/线上并行企业 | 存量商户基础大、覆盖国家广、线下与收单经验深 | 产品体验和开发者心智相对传统，落地常更偏企业项目制 |
| Airwallex | 跨境支付与资金平台 | 全球收款、多币种账户、换汇、发卡、在线支付、订阅管理 | 跨境卖家、出海品牌、全球资金管理需求强的企业 | 跨境资金流、结汇、多币种和财务协同能力突出，亚洲团队普遍更熟悉 | 对某些本地钱包、线下场景或复杂全渠道零售的深度不如 Adyen/Stripe 组合 |
| dLocal | 新兴市场本地支付专家 | 一套 API/合同覆盖拉美、非洲、中东、亚洲多本地支付方式与出款 | 重点做新兴市场扩张的企业 | 新兴市场本地化覆盖强，适合补足传统欧美 PSP 的盲区 | 如果核心市场是欧美成熟市场，其优势不明显；通常作为补充而非唯一方案 |
| Paddle | Merchant of Record (MoR) | 订阅计费、全球税务、结账、支付、开票、续费 | SaaS、软件订阅、数字产品出海 | 把税务、合规和部分交易责任外包，极大降低 SaaS 出海运营复杂度 | 控制权、定价自由度、结账品牌自主度不如自建 PSP 组合；不适合所有实物或平台型场景 |

### 5.1 国际平台的本质差异

#### 全球全栈 PSP

- 代表：`Stripe`、`Adyen`、`Checkout.com`、`Worldpay`
- 特点：一个 API 连接卡组织、本地支付方式、风控、退款、争议、订阅、部分分账和付款能力。
- 适合：你需要自己掌握商户体系、品牌、结账流程与资金路由。

#### 钱包/品牌强化型

- 代表：`PayPal/Braintree`
- 特点：钱包转化强，特别适合 PayPal 认知高的消费市场。
- 适合：欧美 C 端业务、希望提升 PayPal/Venmo 钱包支付占比的团队。

#### 新兴市场强化型

- 代表：`dLocal`
- 特点：覆盖很多传统 PSP 不够强的本地支付方式和出款网络。
- 适合：重点做拉美、东南亚、中东、非洲。

#### MoR 模式

- 代表：`Paddle`
- 特点：平台不是单纯代收款，而是直接承担更多法定销售和税务职责。
- 适合：软件订阅、数字内容、希望极快全球上线的小团队。

## 6. 国内与国际平台分别有什么区别

| 对比维度 | 中国大陆官方直连/门店型聚合 | 国际全栈 PSP | MoR（如 Paddle） |
| --- | --- | --- | --- |
| 主流支付工具 | 微信、支付宝、云闪付、银行卡、扫码 | 卡支付、钱包、本地 APM、银行转账 | 同 PSP，但由平台承担更多法定责任 |
| 典型交易场景 | 线下门店、扫码、公众号/小程序、本地生活 | 跨境电商、SaaS、App、全球收单 | SaaS、数字订阅、软件许可 |
| 技术接入方式 | 可能是聚合码、POS、服务商后台，也可能是 API | 通常是 API first | 通常是托管式结账+订阅平台 |
| 合同与商户主体 | 更强调本地牌照、商户资质、行业类目 | 强调国家/地区准入、KYC/KYB、制裁与税务合规 | 平台承担更多税务和销售责任 |
| 结算与币种 | 人民币为主，本地结算清晰 | 多币种、跨境结算、换汇更重要 | 商户更关注净收入和税后回款 |
| 风控重点 | 套现、商户真实性、线下异常交易 | 欺诈、拒付、跨境风险、地区合规 | 税务、订阅合规、退款/争议和销售责任 |
| 线下能力 | 普遍较强，硬件与服务网络完整 | 差异大，Adyen/Worldpay 更强，Stripe 次之 | 通常不是重点 |
| 订阅/平台分账 | 国内近年在增强，但普遍不如国际平台标准化 | Stripe/Adyen 等成熟度更高 | 订阅最强，但平台控制权更弱 |
| 本地运营支持 | 地推、巡店、硬件、培训、驻场普遍更强 | 主要偏线上运营、客户成功、解决方案团队 | 偏 SaaS 化和合规托管 |

## 7. 各类方案的优劣势总括

| 方案类型 | 优势 | 劣势 | 典型代表 |
| --- | --- | --- | --- |
| 官方直连 | 支付链路更短、原生能力最深、费率和产品政策更清晰 | 多通道统一成本高、技术和对账要自己整合 | 支付宝、微信支付、银联/云闪付 |
| 门店型聚合收单 | 一码/一机/一后台，交付快，本地服务强 | 国际化弱，高级 API 能力一般 | 收钱吧、拉卡拉、移卡 |
| 开发者/平台型聚合 | 统一 API、分账清结算更友好，适合平台业务 | 接入与风控流程更重，商务依赖更高 | 汇付天下、Ping++ |
| 全球全栈 PSP | 全球化最好，订阅/分账/风控/本地支付方式完整 | 价格未必最低，复杂场景实施成本高 | Stripe、Adyen、Checkout.com、Worldpay |
| 新兴市场 PSP | 对本地方法和地区合规覆盖好 | 全球通用性不一定最强 | dLocal |
| MoR | 最省税务和合规心智，适合快速全球卖软件 | 控制权与利润空间相对受限 | Paddle |

## 8. 按场景给出选择建议

### 8.1 中国大陆线下门店

优先顺序通常是：

1. `收钱吧` / `拉卡拉` / `银联商务`
2. `支付宝` / `微信支付` 服务商生态
3. 如需更复杂账务，再看 `汇付天下`

原因：

- 线下场景最看重设备、安装、培训、巡店、门店 SaaS 与售后，而不仅仅是 API。

### 8.2 中国大陆线上业务，想同时接多通道

优先顺序通常是：

1. `支付宝 + 微信支付` 官方直连或服务商模式
2. `汇付天下`
3. `Ping++`

原因：

- 线上业务要平衡官方生态能力与统一支付层，是否需要 `分账/清结算/代发` 是关键分水岭。

### 8.3 跨境电商 / DTC / App 出海

优先顺序通常是：

1. `Stripe`
2. `Adyen`
3. `Checkout.com`
4. `Airwallex`
5. 如涉及新兴市场，再补 `dLocal`

原因：

- 这类业务最看重 `多币种`、`本地支付方式`、`拒付风控`、`订阅/自动续费`、`全球准入`。

### 8.4 全球大型品牌，全渠道零售

优先顺序通常是：

1. `Adyen`
2. `Worldpay`
3. `Checkout.com`
4. `Stripe`

原因：

- 重点是线上线下统一数据、全球收单一致性、跨国复杂组织与企业级 SLA。

### 8.5 SaaS / 软件订阅 / 数字内容出海

优先顺序通常是：

1. `Paddle`：如果你想少管税务和法定销售责任
2. `Stripe Billing`：如果你想保留更高控制权
3. `Adyen`：如果你已经是较大规模全球企业

原因：

- 这类业务不是“谁能收款”这么简单，而是“谁能处理税、账单、续费、退款、失败重试、合规与地区规则”。

## 9. 常见误区

### 误区 1：聚合支付一定更便宜

不一定。  
聚合支付可能节省的是 `接入成本`、`运营成本`、`对账成本` 和 `人力成本`，不一定是名义费率最低。

### 误区 2：官方直连一定更适合所有公司

也不一定。  
如果你的业务需要同时接多个渠道、做平台分账、统一风控、统一报表，官方直连往往反而更重。

### 误区 3：国际 PSP 一定天然适合中国大陆主体

不一定。  
很多国际平台的开户主体、地区准入、行业限制、结算币种和税务要求都有差异，必须以申请时的官方准入政策为准。

### 误区 4：MoR 只是“更高级的支付网关”

不是。  
`MoR` 的核心价值不是支付方式更多，而是把税务、销售主体责任、部分合规和全球订阅复杂度一起打包处理。

## 10. 一个可执行的选型方法

如果你要真正做平台筛选，建议按下面顺序评估：

1. 先定业务场景：`中国本地门店`、`中国线上`、`跨境电商`、`SaaS 订阅`、`平台分账`
2. 再定支付方式：`微信/支付宝/云闪付`、`银行卡`、`PayPal`、`Apple Pay/Google Pay`、`本地 APM`
3. 再定结算诉求：`人民币`、`多币种`、`跨境换汇`、`本地结算`
4. 再定能力诉求：`API`、`订阅`、`分账`、`代发`、`退款/拒付`、`税务`
5. 最后才比较：`费率`、`账期`、`服务`、`上线时间`、`风控门槛`

如果业务复杂，通常不是“只选一个平台”，而是：

- 中国大陆：`官方直连 + 一个聚合服务商`
- 国际：`主 PSP + 补充型本地市场 PSP`
- SaaS：`Billing/PSP + 税务方案` 或直接 `MoR`

## 11. 建议作为补充调研的候选平台

如果你需要继续扩展选型池，还可以补充评估：

- 国际：`Nuvei`、`Rapyd`、`PPRO`、`FastSpring`
- 国内：特定行业支付公司、银行系收单机构、垂直行业 SaaS 收银服务商

这些平台在某些行业或地区也很强，但本文优先展开的是更常见、讨论频率更高的代表性平台。

## 13. 按业务场景再细化一层选型

> 本节更偏“落地选型视角”。如果你已经有目标业务形态，可以直接从对应小节开始看。  
> 其中“强/中/弱”的判断，属于基于官方公开产品能力、文档完备度、行业常见接入方式做出的工程选型推断，并非严格性能基准测试结果。

### 13.1 跨境电商 / DTC / 海外独立站

这类业务最应该看 8 个点：

1. 是否支持目标国家的主流支付方式  
2. 是否有本地收单 / 本地币种显示 / 本地结算  
3. 拒付、欺诈、3DS、风控规则是否成熟  
4. 退款、争议、拒付处理是否顺手  
5. 对账、报表、财务回单是否够细  
6. 是否支持支付链接、托管结账页、无代码快速上线  
7. 是否支持多主体、多地区扩张  
8. 是否支持你真实想卖的品类与地区

| 平台 | 适合度 | 最突出优势 | 主要短板 | 典型使用建议 |
| --- | --- | --- | --- | --- |
| Stripe | 很高 | API、文档、订阅、电商兼容性、迭代速度非常强 | 并非所有地区/主体都最优；复杂线下和超大企业项目未必最佳 | 适合作为出海独立站、App、SaaS 的第一主 PSP |
| Adyen | 很高 | 全球企业级收单、统一线上线下、企业级稳定性 | 接入与商务流程偏重 | 更适合大型品牌、多国家多门店、全渠道零售 |
| Checkout.com | 高 | 全球线上支付表现均衡、Unified Payments API、支付性能优化思路清晰 | 更偏中大型线上商户，自助化不如 Stripe | 适合跨境电商和大中型线上业务 |
| Airwallex | 很高 | 支付 + 多币种账户 + 换汇 + 全球资金管理一体化 | 某些线下或极重型零售能力不如 Adyen | 适合跨境品牌、卖家、需要强资金管理的企业 |
| PayPal / Braintree | 中到高 | PayPal 钱包转化强，适合欧美 C 端 | 不能完全替代主 PSP | 适合作为辅助支付方式提升转化 |
| dLocal | 高（新兴市场） | 拉美、中东、非洲、部分亚洲新兴市场的本地支付方式覆盖强 | 在欧美成熟市场不是最强主选 | 适合作为新兴市场补充 PSP |

推荐组合思路：

- 北美 / 欧洲为主：`Stripe + PayPal`
- 多国家大品牌：`Adyen` 或 `Checkout.com` 为主，再补 `PayPal`
- 强跨境资金流需求：`Airwallex + PayPal`
- 拉美 / 中东 / 非洲扩张：`Stripe/Adyen/Airwallex + dLocal`

### 13.2 SaaS 订阅 / 软件服务 / 数字内容

这类业务与普通电商最大的不同，是你真正买的不是“收款”能力，而是“持续收费系统”：

- 周期计费
- 升降配
- 试用期
- 按量计费
- 失败重试
- 发票与税
- 退款与账单调整
- 订阅生命周期 Webhook

| 平台 | 适合度 | 适合原因 | 不适合原因 |
| --- | --- | --- | --- |
| Paddle | 很高 | `MoR` 模式能把全球税务、合规、部分争议压力一起打包处理，非常适合 SaaS 和数字产品 | 控制权更低，品牌和结账流程自定义空间不如自建 PSP |
| Stripe Billing | 很高 | 订阅、试用、账单、Webhook、Connect、二次开发生态都很成熟 | 你仍需自己承担更多税务和主体合规责任 |
| Airwallex Billing / Subscription Management | 高 | 适合跨境团队，支付、账单、多币种和资金管理链路更统一 | 生态成熟度与历史沉淀通常仍低于 Stripe Billing |
| PayPal / Braintree | 中 | 适合作为 PayPal 用户偏好的补充支付方式，尤其在欧美 | 不建议单独作为复杂 SaaS 订阅的唯一核心账单系统 |
| Adyen | 中到高 | 更适合已有规模、对全球企业级统一支付要求高的团队 | 对中小 SaaS 团队来说通常偏重 |

简单判断：

- 想最快合规出海卖 SaaS：优先 `Paddle`
- 想自己掌控订阅、计费和支付链路：优先 `Stripe Billing`
- 想把多币种资金、收款、换汇和账单放在一起：看 `Airwallex`

### 13.3 连锁门店 / 餐饮零售 / 本地生活

门店场景经常高估“API”，低估“交付”。

线下连锁更应该看：

- POS / 收银机 / 扫码枪 / 小票打印机
- 门店装机、巡检、培训、售后
- 多门店、多店员、多班次管理
- 店长报表、总部报表、门店分账
- 点餐、外卖、自提、会员、营销联动

| 平台 | 适合度 | 最突出优势 | 主要短板 |
| --- | --- | --- | --- |
| 收钱吧 | 很高 | 门店聚合码、收银和经营 SaaS 一体化强，上线很快 | 更偏线下，本身不是全球化 PSP |
| 拉卡拉 | 很高 | 终端设备、银行卡收单、传统门店覆盖很强 | API 抽象与开发者体验通常不如纯互联网 PSP |
| 银联商务 / 云闪付生态 | 很高 | 银行卡与线下收单基础设施强、大型连锁与政企接受度高 | 产品灵活性一般，互联网化速度未必最快 |
| 微信支付 / 支付宝官方生态 | 高 | 小程序、生活号、会员、券、营销闭环强 | 不是“多通道统一后台”；要自己做整合 |
| 汇付天下 | 中到高 | 如果门店背后还有平台、清结算、分账等复杂资金路由，会更有价值 | 比单纯门店收银产品更重 |

门店型企业常见的正确姿势不是“只选一个”：

- `门店聚合服务商` 负责收银、码牌、终端、门店 SaaS
- `支付宝/微信支付` 负责官方生态深能力
- 有复杂分账或总部清结算需求时，再补 `汇付天下` 这类平台型方案

### 13.4 平台分账 / Marketplace / SaaS 平台代商户收款

这是很多团队最容易误判的场景。  
“能收款”不等于“能合法、稳定、可对账地帮别人收款再分给别人”。

这类业务要重点确认：

- 商户 / 子商户 / Connected Account 的开户与 KYC/KYB
- 分账、冻结、解冻、留存、调账
- 退款、拒付时由谁承担
- 平台抽佣怎么做
- 结算周期和负余额怎么处理
- 合同结构到底是 PSP、服务商、还是平台资金方案

| 平台 | 适合度 | 核心能力 | 注意点 |
| --- | --- | --- | --- |
| Stripe Connect | 很高 | Connected Accounts、平台收款、自动分账、打款、平台费 | 控制力强，但平台也要承担较多业务设计责任 |
| Adyen for Platforms | 很高 | 平台入驻、分账、打款、风险和报表能力都很强 | 更适合中大型平台，实施偏项目制 |
| Airwallex Payments for Platforms | 很高 | Connected accounts、自动分账、全球 payout、且支持 PSP-agnostic 路由 | 很适合跨境平台，但需要认真设计资金流与主体结构 |
| 微信支付分账 / 服务商模式 | 高（中国大陆） | 官方分账能力成熟，适合本地平台、品牌、服务商 | 行业、产品、比例、流程通常受业务规则约束 |
| 汇付天下 | 很高（中国大陆） | 更偏平台账务、清结算、分账、代发等复杂场景 | 偏 B 端项目，需要较完整商务和风控评估 |
| dLocal | 中到高 | 对跨境平台的新兴市场收款与付款补位价值高 | 常作为补充方案而不是全局唯一方案 |

## 15. 如果你的项目是 AI / API 充值平台，可以这样选

结合本仓库这类 `API 网关 / 账户充值 / 订阅` 场景，通常更关心的是：

- 用户是否能快速充值
- 充值回调是否稳定
- 订阅和套餐是否好做
- 企业客户是否支持银行转账 / 发票 / 对账
- 是否能做全球付款与本地钱包补充

### 15.1 面向中国大陆用户充值

更实用的组合通常是：

- `微信支付 + 支付宝` 官方直连或服务商模式
- 如果你想更快落地统一收款页、对账和商户交付，可补 `汇付天下` 或成熟服务商方案

更看重的不是“国际化”，而是：

- 支付成功率
- 回调稳定性
- 支付风控
- 商户主体进件速度
- 对账与补单流程

### 15.2 面向海外开发者或团队充值

更实用的组合通常是：

- `Stripe` 作为主 PSP
- `PayPal` 作为辅助钱包方式
- 如果你需要更强跨境资金管理和企业付款，再补 `Airwallex`

如果你做的是：

- `按月订阅`：优先看 `Stripe Billing`
- `年付套餐 + 全球税务合规压力大`：优先看 `Paddle`
- `大客户合同收款 + 多币种结算 + 付款给合作伙伴`：看 `Airwallex`

### 15.3 一个很容易忽视的合规提醒

如果你的产品涉及：

- 预充值余额
- API 点数 / credits
- 钱包余额
- 代充值
- 转售第三方服务

那么在接入前一定要向支付平台确认：

- 你的业务类目是否允许
- 预付余额是否有额外限制
- 是否会被认定为“存储价值”“转售”“代理销售”或其他受限模式

这一步比“技术能不能接”更重要。
