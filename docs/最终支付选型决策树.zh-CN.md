# 最终支付选型决策树

更新时间：2026-04-20

## 1. 这份文档怎么用

这份文档不是平台百科，而是帮你快速回答一个问题：

> 结合你当前业务阶段、主体条件和目标市场，最适合走哪条支付路线？

它基于当前这轮会话里已经整理过的推荐逻辑，把路线压缩成一棵“从上往下判断”的决策树。

适合解决：

- 我到底先上国内聚合平台、官方直连，还是国际平台
- 我做的是充值、订阅、还是跨境电商，该先看哪家
- 我是个人 / 小团队 / 企业主体，路线怎么选
- 我现在资源有限，哪条路最现实

配套阅读建议：

- `docs/国外平台与国内平台及官方直连三方对照表.zh-CN.md`
- `docs/国外平台详细分场景选型表.zh-CN.md`
- `docs/会话历史中13至14号国内外聚合支付平台推荐汇总.zh-CN.md`
- `docs/项目专用最终支付配置清单.zh-CN.md`

## 2. 第一层：你的主市场到底在哪里

先不要先看平台名，先回答：

### 2.1 你的主要付费用户在哪

只需要先分 3 类：

1. 中国大陆为主
2. 海外为主
3. 国内和海外都要

这是第一道分叉，因为：

- 中国大陆支付，核心是支付宝 / 微信 / 云闪付生态
- 海外支付，核心是卡支付、本地支付方式、订阅、税务、结算
- 两者解决的问题完全不同

---

## 3. 决策树总览

```text
开始
├─ A. 主要用户在中国大陆
│  ├─ A1. 现在最想快上线、少改代码
│  │  └─ 先走国内聚合平台（epay 类），后续再切官方直连
│  ├─ A2. 已有正式商户能力，想长期稳定
│  │  └─ 直接做支付宝/微信官方直连
│  └─ A3. 还没有正式商户能力，也不想接第三方平台
│     └─ 临时人工充值 / 静态码过渡，但不建议长期使用
│
├─ B. 主要用户在海外
│  ├─ B1. 你是 SaaS / API 平台 / 开发者产品
│  │  ├─ 想自己掌控支付链路 -> Stripe
│  │  └─ 想少管税务和法定销售责任 -> Paddle
│  ├─ B2. 你是中大型国际线上业务 / 跨境电商
│  │  ├─ 中大型线上主收单 -> Checkout.com
│  │  └─ 企业级多国家复杂收单 -> Adyen
│  ├─ B3. 你很在意多币种和跨境资金管理
│  │  └─ Airwallex
│  ├─ B4. 你重点做新兴市场
│  │  └─ dLocal
│  └─ B5. 你主要想补欧美钱包支付转化
│     └─ PayPal / Braintree 作为补充
│
└─ C. 国内和海外都要
   ├─ 国内主链路 -> 官方直连（或短期 epay 聚合作为过渡）
   ├─ 海外主链路 -> Stripe / Paddle / Adyen 等单独一套
   └─ 不建议用一套平台硬覆盖全部市场
```

## 4. 分支 A：主要用户在中国大陆

## 4.1 A1：你现在最重要的是“尽快上线、尽量少改代码”

如果你符合这些特征：

- 还在项目早期
- 想先验证充值闭环
- 不想大改 `new-api`
- 当前项目已经有旧 `epay` 链路

那么优先建议：

- **国内聚合平台**
- 更具体说，就是：
  - 兼容 `epay / 易支付` 协议的平台

### 为什么

- 当前 `new-api` 旧链路原生就支持这类平台
- 已有：
  - `/api/user/pay`
  - `/api/user/epay/notify`
  - `go-epay`
- 上线速度快
- 改动量最小

### 对应平台路线

- 第一阶段：`epay` 类聚合平台
- 第二阶段：官方直连并行
- 第三阶段：再决定是否下线旧聚合通道

### 典型代表

- `ZPAY`
- 以及其他兼容 `epay` 协议的平台

---

## 4.2 A2：你已经有正式商户能力，想长期稳定

如果你符合这些特征：

- 已经具备支付宝官方参数
- 已经具备微信支付商户参数
- 愿意承担正式接入和联调成本
- 更在意长期可控性

那么优先建议：

- **支付宝官方直连**
- **微信支付官方直连**

### 为什么

- 支付链路更短
- 回调和对账更清晰
- 长期依赖更少
- 更适合正式生产链路

### 当前项目里的现实建议

- 支付宝官方和微信官方作为主链路
- 如担心风险，可短期保留旧 `epay` 聚合平台作备用

---

## 4.3 A3：你现在还没有正式商户能力，也不想接第三方平台

如果你符合这些特征：

- 还没有完整商户资料
- 也不想先接聚合平台
- 只是临时测试收款

那只能短期考虑：

- **人工充值**
- **静态收款码**

### 但这里的结论很明确

- 只能临时过渡
- 不适合正式上线长期使用

### 为什么

- 无法自动到账
- 无法标准化对账
- 运维和人工审核成本高
- 风险大

---

## 5. 分支 B：主要用户在海外

## 5.1 B1：你是 SaaS / API 平台 / 开发者产品

这是之前会话里最常被提到的国际主场景之一。

### 如果你更想自己掌控支付链路

优先建议：

- `Stripe`

#### 原因

- 开发者体验强
- API 成熟
- Checkout、Billing、Webhook 都很成熟
- 适合开发者产品和 API 平台

### 如果你更想少管税务和法定销售责任

优先建议：

- `Paddle`

#### 原因

- 更适合 SaaS / 数字产品订阅
- `MoR` 模式更能减轻一部分税务与法定销售责任压力

### 这一分支的一句话判断

- 重控制权：`Stripe`
- 重合规托管：`Paddle`

---

## 5.2 B2：你是中大型国际线上业务 / 跨境电商

如果你符合这些特征：

- 国际交易量较大
- 线上支付是核心
- 想认真对比国际 PSP

优先建议：

- `Checkout.com`
- `Adyen`

### 如何分

#### 更偏中大型国际线上业务

- 看 `Checkout.com`

#### 更偏多国家、多渠道、企业级统一收单

- 看 `Adyen`

### `Stripe` 在这里还要不要看

要。

但很多时候在这个分支里：

- `Stripe` 更像强备选
- `Checkout.com` / `Adyen` 更像更接近企业级对标项

---

## 5.3 B3：你特别在意多币种和跨境资金管理

如果你不只是要“收款”，还特别在意：

- 多币种账户
- 换汇
- 跨境结算
- 全球资金流协调

优先建议：

- `Airwallex`

### 为什么

因为它的价值不只是支付通道，还包括：

- 资金管理
- 结算效率
- 多币种财务协同

### 它最适合什么

- 跨境品牌
- 多地区收款
- 对资金流效率和多币种运营要求较高的团队

---

## 5.4 B4：你重点做新兴市场

如果你重点区域在：

- 拉美
- 中东
- 非洲
- 某些亚洲新兴市场

优先建议：

- `dLocal`

### 为什么

因为它更适合补：

- 传统欧美主 PSP 在新兴市场本地支付方式上的覆盖短板

### 这时是不是只用 `dLocal`

通常不建议。

更常见的现实结构是：

- 主 PSP：`Stripe` / `Adyen` / `Airwallex`
- 新兴市场补强：`dLocal`

---

## 5.5 B5：你主要想补欧美钱包支付转化

如果你的用户主要在欧美，而且你发现：

- 钱包支付转化很重要
- 用户更愿意用 `PayPal`

那么应考虑：

- `PayPal / Braintree`

### 但它在这里通常是什么角色

更像：

- 补充支付方式

而不是：

- 所有复杂国际支付需求的唯一核心平台

---

## 6. 分支 C：国内和海外都要

这是很多团队后面会遇到的情况。

### 这里最重要的判断

不要幻想：

- 一套平台优雅覆盖中国大陆官方扫码、国际卡支付、订阅、税务托管、海外本地支付方式

大多数情况下，更现实的是：

## 6.1 国内单独一条主链路

- 长期：支付宝 / 微信官方直连
- 短期过渡：国内 `epay` 聚合平台

## 6.2 海外单独一条主链路

根据业务类型选择：

- `Stripe`
- `Paddle`
- `Adyen`
- `Checkout.com`
- `Airwallex`
- `dLocal`

### 这条分支的一句话建议

> 国内和海外最好拆成两套主链路，不要强行一锅煮。

---

## 7. 按你的项目阶段再压一次判断

## 7.1 你现在是早期项目

### 国内

- 先用国内聚合平台快速上线

### 海外

- 先用 `Stripe`
- 如果是订阅导向且想少管合规，再看 `Paddle`

## 7.2 你现在已经进入稳定增长阶段

### 国内

- 优先切官方直连

### 海外

- 开始认真比较 `Adyen`、`Checkout.com`、`Airwallex`
- 新兴市场再补 `dLocal`

## 7.3 你现在已经是平台型 / 企业级业务

### 国内

- 官方直连 + 必要的服务商 / 平台能力

### 海外

- `Adyen`
- `Checkout.com`
- `Airwallex`
- `Stripe Connect`

更值得纳入企业级比较清单

---

## 8. 最后一张速判表

| 你最在意什么 | 最优先看谁 |
| --- | --- |
| 出海开发者产品 | `Stripe` |
| SaaS 订阅 + 少管税务 | `Paddle` |
| 企业级全球收单 | `Adyen` |
| 中大型国际线上支付 | `Checkout.com` |
| 多币种资金管理 | `Airwallex` |
| 新兴市场支付方式 | `dLocal` |
| 欧美钱包支付转化 | `PayPal / Braintree` |
| 国内快上线少改代码 | 国内 `epay` 聚合平台 |
| 国内长期稳定 | 支付宝 / 微信官方直连 |

---

## 9. 一句话版结论

如果只给一句最终建议：

> 海外默认先看 `Stripe`，订阅税务托管看 `Paddle`，企业级全球收单看 `Adyen` / `Checkout.com`，资金流看 `Airwallex`，新兴市场看 `dLocal`；国内则优先在“官方直连”和“`epay` 聚合平台过渡方案”之间做阶段性选择。
