# `new-api` 静态收款码问题、商户号优点与支付宝/微信商户申请指南

更新时间：2026-04-19

## 1. 这份文档是给谁看的

这份文档面向两类人：

- 正在用“个人支付宝 / 个人微信静态收款码”临时收款，准备升级成正式支付接入的人
- 准备把本项目的充值流程做成“下单 -> 扫码 -> 自动到账 -> 自动回调更新订单”的人

如果你只想先看结论，可以直接记住一句话：

> 对 `new-api` 这种“站内充值、需要自动记账、需要按订单发放额度”的系统来说，静态收款码只能做临时过渡；正式上线应尽快切换到支付宝官方商户接入 + 微信支付商户号接入。

## 2. 本项目当前最适合的支付模式

结合当前代码与现有支付实现文档，本项目现在最适合的是：

- 支付宝：`当面付` / 扫码支付，核心是 `alipay.trade.precreate`
- 微信支付：`Native` 扫码支付，核心是 API v3 `/v3/pay/transactions/native`
- 接入模式：单商户、自营、直连接入

也就是说，当前项目更适合：

- 你自己的主体
- 你自己的支付宝应用
- 你自己的微信支付商户号
- 你自己的 `AppID`
- 你自己的站点直接收款

而不是：

- 服务商代商户模式
- 一套系统给很多外部商户做统一代收
- 子商户 / 多商户路由

## 3. 静态收款码有什么问题

下面这部分是从工程实现、财务对账、风控和运营角度做的归纳总结。它不是某一家支付平台的官方处罚条文，而是把“静态码”和“官方商户接口”放在一起比较后的实际问题清单。

### 3.1 先看一句最直白的话

静态收款码本质上只是“给用户一个扫一扫入口”，它天然不带“订单系统能力”。

而 `new-api` 需要的是：

- 用户 A 充多少钱
- 对应哪个订单
- 支付是否真的成功
- 成功后什么时候给账户加余额
- 超时未支付怎么办
- 重复通知 / 重复充值怎么办
- 财务月底怎么对账

这些都不是静态码擅长处理的事情。

### 3.2 核心问题总表

| 问题 | 静态收款码会发生什么 | 在 `new-api` 里的直接后果 |
| --- | --- | --- |
| 不能绑定订单 | 二维码固定不变，码里通常不含你系统生成的业务订单号 | 你无法天然知道“这笔钱是给哪个充值单付的” |
| 没有标准异步回调 | 用户付完钱后，系统通常收不到官方服务器通知 | 不能自动给用户加余额，只能靠人工核对 |
| 无法强约束支付金额 | 用户可能少付、多付、分几次付、备注乱填 | 充值金额与订单金额容易不一致 |
| 无法稳定查支付状态 | 很难用标准 API 主动查“这笔订单到底成没成功” | 订单会卡在“待支付”，要人工确认 |
| 不方便做幂等处理 | 同一用户重复提交截图、重复申诉时，难以自动判重 | 容易重复入账或漏入账 |
| 退款流程不标准 | 很难做到“按原支付单退款” | 售后体验差，财务留痕也弱 |
| 对账效率低 | 通常需要看聊天记录、收款记录、人工 Excel 对账 | 运营量一大就很痛苦 |
| 权限和审计弱 | 个人码常常和个人账户绑死 | 员工交接、权限控制、日志留存都不好做 |
| 风控与合规压力更大 | 业务收款和个人收款混用，解释成本高 | 一旦量起来，更容易遇到风控、限额、核验问题 |
| 用户体验差 | 用户付完后常常还要上传截图或等人工确认 | 成交转化率和信任感都会下降 |

### 3.3 对本项目最致命的 5 个问题

如果只挑最影响上线质量的 5 个点，分别是：

1. **无法自动识别订单**
   - 用户扫的是同一张固定码。
   - 系统不知道这笔钱属于哪一个充值订单。

2. **无法自动到账**
   - 没有稳定的官方回调，系统很难在“用户付款成功后立刻加余额”。

3. **金额不受控**
   - 你希望用户充 `100`，用户可能付了 `99.99`、`100.01` 或者干脆多次转入。
   - 自动匹配会变得非常脆弱。

4. **财务无法标准化对账**
   - 量小的时候还能人工看。
   - 一旦用户数起来，人工核对就是灾难。

5. **不利于后续做正式风控与售后**
   - 退款、争议单、误充值、重复支付、超时未支付等场景都很难标准化处理。

### 3.4 静态码还能不能继续用

可以，但更适合下面这些场景：

- 内部测试
- 小范围试运营
- 你愿意完全人工审核充值
- 日单量非常低
- 接受“到账慢、偶尔错单、需要人工介入”

如果你的目标是：

- 公开上线
- 用户自助充值
- 自动加余额
- 自动回调
- 可审计、可对账、可退款

那就不应该继续长期依赖静态收款码。

## 4. 如果改成支付宝 / 微信商户号，有什么优点

### 4.1 一句话总结

商户号的价值，不只是“能收钱”，而是“能把收钱这件事变成一个标准化、可编程、可追踪、可对账的系统流程”。

### 4.2 对项目最有价值的优点

| 能力 | 商户号 / 官方接口能做什么 | 对 `new-api` 的价值 |
| --- | --- | --- |
| 订单化收款 | 下单时生成业务订单号，并把金额、商品、回调地址一起带上 | 每笔充值都能和系统订单一一对应 |
| 异步回调 | 支付成功后，官方服务器通知你的系统 | 可自动把订单从“待支付”改成“已支付” |
| 主动查单 | 订单状态可通过官方 API 再查一次 | 可处理回调丢失、网络抖动、用户申诉 |
| 金额校验 | 每个订单金额在下单时就固定 | 减少“少付 / 多付 / 金额错配” |
| 幂等处理 | 同一订单号可以做重复通知防重 | 避免重复加余额 |
| 退款与关单 | 支持标准化退款、关闭未支付订单 | 售后和超时订单处理更规范 |
| 对账单 | 可下载或查询官方账单 | 财务对账更容易 |
| 权限管理 | 商户平台可分角色管理 | 比个人码更适合团队协作 |
| 安全能力 | 私钥、证书、签名、验签、回调校验 | 交易链路可信度更高 |
| 品牌与合规 | 用正式商户主体收款 | 更适合长期经营和正式上线 |

### 4.3 对用户体验的直接提升

商户号接入后，用户看到的体验会明显更像“正常网站支付”：

- 点充值 -> 立即生成专属二维码
- 支付成功后系统自动刷新状态
- 不需要上传付款截图
- 不需要等管理员手工审核
- 出现异常时可以查订单、补单、退款

### 4.4 对运维和财务的直接提升

- 你可以按订单号追踪每一笔充值
- 你可以记录完整支付链路日志
- 你可以把“充值成功后加余额”做成幂等逻辑
- 你可以把“超时未支付”做成自动关单
- 你可以基于官方账单做日结、周结、月结

## 5. 申请前先做的准备

不要一上来就点“申请商户号”。先把下面这些准备好，成功率会高很多。

### 5.1 先决定主体类型

对于本项目这种正式充值业务，最推荐的主体顺序是：

1. 企业
2. 个体工商户

补充说明：

- 支付宝帮助中心提到，个人或企业账户都可能申请接口，但具体仍要看产品准入条件。
- 从实际经营、审核、结算、风控、税务、对账角度看，**正式上线更建议企业或个体工商户主体**。
- 微信支付普通商户入驻支持的主体类型，官方页面明确列出了：个体工商户、企业、政府机关、事业单位、社会组织。

### 5.2 先决定业务场景

本项目当前建议选择：

- 支付宝：当面付 / 扫码支付
- 微信支付：PC 网站场景下的 `Native` 支付

不要一开始就选错成：

- 服务商模式
- 小程序专用方案
- 多商户代收方案

### 5.3 准备通用材料

一般都要提前准备这些：

- 营业执照
- 法人 / 经营者身份证正反面
- 银行账户信息
- 联系手机号
- 联系邮箱
- 商户联系人信息
- 经营类目说明
- 你的网站、APP、后台截图或业务说明

### 5.4 准备可联调的线上环境

至少建议准备：

- 公网可访问域名
- HTTPS
- 能稳定访问的回调地址
- 一个能展示充值二维码的页面

额外注意：

- 微信支付 PC 网站接入指引明确要求“**完成域名 ICP 备案的网站**”接入支付。
- 支付宝帮助中心则强调“网站或手机客户端建设完好，产品或服务信息丰富”。

## 6. 支付宝申请步骤：小白版

### 6.1 你最终要拿到什么

先别把支付宝想成“我只要一个商户号”。

对本项目当前代码来说，支付宝这边你最终真正要拿到的是：

- `AppId`
- 应用私钥
- 支付宝公钥
- 支付网关地址
- 对应的支付产品能力（当前是当面付扫码支付）

也就是说，支付宝更像是：

- 先用商家主体完成认证 / 签约
- 再在开放平台创建支付应用
- 最后把应用参数接入项目

### 6.2 步骤 1：准备并认证支付宝账号

你要做的事：

- 有支付宝账号就登录
- 没有就先注册
- 完成实名认证
- 按页面要求完成升级认证

官方帮助中心给出的通用签约流程里，前几步就是：

- 选择产品
- 实名认证、升级认证
- 填写申请信息
- 后续再进入系统集成

建议你这里就准备好：

- 营业执照
- 法人信息
- 银行卡 / 对公账户信息
- 联系方式

### 6.3 步骤 2：确认你申请的是“当面付”而不是“收钱码”

在支付宝商家中心的产品与服务里，官方把下面几类能力分开了：

- 电脑网站支付
- 手机网站支付
- APP 支付
- 当面付
- 收钱码

对 `new-api` 当前“PC 页面展示二维码，用户手机扫码充值”的场景，应该优先看：

- **当面付**

不要把“静态收钱码”和“官方扫码接口”混在一起：

- 收钱码更偏工具型收款
- 当面付更适合系统化接入和自动化下单

### 6.4 步骤 3：进入商家中心发起产品申请

建议操作路径：

1. 打开支付宝商家中心：`https://b.alipay.com/`
2. 进入“产品与服务”
3. 找到“当面付”
4. 点击“我要接入”或“在线申请”

根据支付宝帮助中心与商家中心常见路径，接下来一般会让你做这些事：

- 选择经营类目
- 填写商户经营信息
- 填写商户联系人信息
- 上传营业执照、网站 / APP 信息、必要资质
- 提交审核

这里最容易卡住的点是：

- 行业类目选错
- 特殊行业资质不全
- 网站还没建设完整
- 网站内容与营业执照经营范围对不上

### 6.5 步骤 4：等待审核

支付宝不同页面给出的时效并不完全一样，常见口径包括：

- 商家认证资料人工审核约 2 天
- 银行卡打款验证约 3 个工作日
- 某些自助签约产品示例写的是 5 个工作日内审核
- 某些产品页写的是约 1 个工作日

所以更稳妥的理解是：

> 支付宝各环节审核时效会因产品、主体、资料完整度不同而变化，最终以你申请页面的实时提示为准。

### 6.6 步骤 5：到开放平台创建应用

产品申请不是全部，你还要去支付宝开放平台创建应用。

建议操作路径：

1. 打开：`https://open.alipay.com/module/webApp`
2. 登录支付宝开放平台
3. 创建“网页 / 移动应用”
4. 填写应用名称、应用图标、应用说明、站点信息等
5. 拿到应用的 `AppId`

这里要记住：

- **本项目里用的是 `AppId`，不是把支付宝账号本身直接填进代码里**
- `AppId` 也不是 PID / UID / 收款账号

### 6.7 步骤 6：配置密钥

当前项目里的支付宝实现采用的是“公钥模式”，不是证书模式。

你要做的是：

1. 在本机或服务器生成 RSA 密钥对
2. 本地保存“应用私钥”
3. 把“应用公钥”上传到支付宝开放平台
4. 从开放平台获取“支付宝公钥”

最后项目里真正要填的是：

- `AlipayOfficialAppId`
- `AlipayOfficialPrivateKey`
- `AlipayOfficialPublicKey`
- `AlipayOfficialGateway`

注意不要填错：

- 应用私钥 != 应用公钥
- 应用公钥 != 支付宝公钥
- `AppId` != 支付宝账号

### 6.8 步骤 7：按页面提示补充能力并提交应用审核

支付宝开放平台搜索结果和页面说明里明确提到：

- 不同站点 / 服务要创建不同应用
- 应用开发完成后，需要自行验收和安全检查
- 然后再提交平台审核

因此实操上你通常会继续做：

- 给应用添加支付能力
- 确认回调域名 / 安全配置
- 根据页面要求提交审核 / 上线

### 6.9 步骤 8：先用沙箱或小额联调，再切正式

对本项目来说，最稳妥的顺序是：

1. 先拿测试参数联调
2. 验证二维码拉起、支付成功、回调成功、查单成功
3. 再切正式参数

当前项目的支付宝网关：

- 正式：`https://openapi.alipay.com/gateway.do`
- 沙箱：`https://openapi.alipaydev.com/gateway.do`

### 6.10 步骤 9：填入本项目并联调

当前项目最终要填的支付宝字段如下：

| 项目字段 | 你应该填什么 |
| --- | --- |
| `AlipayOfficialEnabled` | 联调前先关，确认成功后再开 |
| `AlipayOfficialAppId` | 支付宝开放平台应用的 `AppId` |
| `AlipayOfficialPrivateKey` | 你本地生成并保存的应用私钥 |
| `AlipayOfficialPublicKey` | 支付宝开放平台提供的支付宝公钥 |
| `AlipayOfficialGateway` | 正式或沙箱网关地址 |

## 7. 微信支付商户号申请步骤：小白版

### 7.1 你最终要拿到什么

对本项目当前代码来说，微信支付这边你最终要拿到的是：

- 商户号 `mchid`
- 与商户号绑定的 `AppID`
- 商户 API 证书私钥
- 商户 API 证书序列号
- APIv3 Key
- 微信支付平台证书

当前项目对应字段为：

- `WeChatPayOfficialAppId`
- `WeChatPayOfficialMchId`
- `WeChatPayOfficialSerialNo`
- `WeChatPayOfficialPrivateKey`
- `WeChatPayOfficialAPIv3Key`
- `WeChatPayOfficialPlatformCert`

### 7.2 步骤 1：确认你走的是“普通商户模式”

微信官方文档把接入模式区分为：

- 普通商户模式
- 服务商模式

对于当前项目，优先选择：

- **普通商户模式**

原因很简单：

- 你是自己的网站自己收款
- 当前项目也没有服务商多商户路由

### 7.3 步骤 2：先准备微信支付申请材料

微信支付 PC 网站接入指引给出的材料清单非常清楚。

#### 个体工商户

- 营业执照
- 对公银行账户 / 法人对私账户
- 法人身份证

#### 企业

- 营业执照
- 组织机构代码证（如已三证合一则无需单独提供）
- 对公银行账户
- 法人身份证

#### 机关、事业单位、社会组织等

- 营业执照或主体证明材料
- 组织机构代码证（如已三证合一则无需单独提供）
- 对公银行账户
- 法人身份证

额外要求：

- 如果你走的是 PC 网站场景，网站应已完成 ICP 备案

### 7.4 步骤 3：发起普通商户入驻申请

建议操作路径：

1. 打开微信支付接入指引：`https://pay.wechatpay.cn/static/applyment_guide/applyment_detail_website.shtml`
2. 选择“我有 PC 网站”
3. 点击“接入微信支付”
4. 在线提交营业执照、身份证、银行账户等基本信息
5. 按页面指引完成账户验证

微信官方接入指引给出的申请流程是：

1. 提交资料
2. 签署协议
3. 绑定场景

### 7.5 步骤 4：等待审核并签协议

微信官方接入指引给出的审核节奏是：

- 微信支付团队通常会在 **1-2 个工作日** 内完成审核
- 审核通过后，需要在线签约

`mchid与appid申请` 文档还提到：

- 商户号申请成功后，官方会向你填写的联系邮箱发送通知邮件
- 邮件中会包含申请成功的 `mchid` 以及登录账号密码

所以这里你一定要：

- 确认申请邮箱可正常收信
- 把邮件、账号、密码安全保存

### 7.6 步骤 5：并行申请 `AppID`

这一点非常容易被忽略，但对本项目非常关键。

微信官方文档明确说：

- `mchid` 和 `appid` 的申请可以并行进行
- `appid` 可以来自：
  - 微信公众平台（服务号 / 公众号 / 小程序）
  - 微信开放平台（移动应用）

对本项目当前代码来说，你最终必须有一个**已经和收款商户号绑定的 `AppID`**。

如果你还没有 `AppID`，就按自己的业务载体选择：

- 有公众号 / 服务号：去公众平台注册
- 有小程序：去公众平台注册小程序
- 有移动 App：去开放平台注册移动应用

### 7.7 步骤 6：把 `mchid` 和 `AppID` 绑定

这一步不能省。

微信官方文档明确要求：

- `appid` 必须和 `mchid` 进行绑定

并且官方页面说明：

- 若 `AppID` 与商户号主体一致，通常可自助绑定
- 若主体不一致，通常需要补充联合经营材料或承诺函，并等待审核

所以，最省事的做法是：

- **尽量让 `AppID` 主体和商户号主体一致**

### 7.8 步骤 7：确认支付场景和产品

微信支付 PC 网站接入指引明确写到：

- PC 网站可以接 `JSAPI` 支付或 `Native` 支付

结合当前项目的实现，应该优先确认：

- 选择 `Native` 支付
- 用户在 PC 页面看到二维码
- 用户用微信扫一扫完成付款

### 7.9 步骤 8：准备 API v3 开发参数

微信支付官方“开发必要参数说明”列得很清楚，普通商户开发前通常要准备：

- `mchid`
- `appid`
- 商户 API 证书
- 商户 API 证书序列号
- 微信支付公钥或平台证书
- APIv3 Key

但要注意一个项目细节：

> 微信官方现在同时支持“微信支付公钥模式”和“平台证书模式”；而本项目当前代码仍然要求你填写“平台证书内容”。

所以对 `new-api` 来说，你要按下面顺序准备：

1. 申请商户 API 证书
2. 保存商户私钥
3. 记录商户 API 证书序列号
4. 在商户平台设置 APIv3 Key
5. 下载微信支付平台证书

### 7.10 步骤 9：把参数填入本项目

当前项目最终要填的微信字段如下：

| 项目字段 | 你应该填什么 |
| --- | --- |
| `WeChatPayOfficialEnabled` | 联调前先关，联调通过后再开 |
| `WeChatPayOfficialAppId` | 已和 `mchid` 绑定的 `AppID` |
| `WeChatPayOfficialMchId` | 微信支付商户号 |
| `WeChatPayOfficialSerialNo` | 商户 API 证书序列号 |
| `WeChatPayOfficialPrivateKey` | 商户 API 证书对应的私钥 PEM |
| `WeChatPayOfficialAPIv3Key` | 你在商户平台设置的 32 位 APIv3 Key |
| `WeChatPayOfficialPlatformCert` | 微信支付平台证书 PEM 内容 |

### 7.11 步骤 10：完成回调联调

你最终还要验证这些链路：

- 下单成功
- 二维码展示成功
- 用户扫码成功
- 支付成功回调成功
- 查单成功
- 订单状态正确更新
- 重复回调不会重复入账
- 超时订单可关闭

## 8. 支付宝和微信，申请时最容易搞混的地方

### 8.1 支付宝常见误区

- `AppId` 不是支付宝登录账号
- `AppId` 不是 PID / UID
- 应用私钥不是支付宝公钥
- 应用公钥不是项目里要填的那个公钥
- “静态收钱码”不等于“当面付扫码接口”

### 8.2 微信支付常见误区

- `mchid` 不是 `AppID`
- `AppID` 不绑定 `mchid` 就不能直接拿来用
- 商户 API 证书序列号不是平台证书序列号
- 商户私钥不是平台证书
- APIv3 Key 不是私钥文件
- 你现在项目里要填的是“平台证书”，不是“微信支付公钥”

## 9. 给小白的最短执行清单

如果你只想按顺序办事，可以直接照这个清单走。

### 9.1 支付宝最短清单

1. 准备企业或个体工商户主体资料
2. 准备完整网站 / 业务说明 / 联系方式
3. 在 `https://b.alipay.com/` 登录并找到“当面付”
4. 提交资料并等待审核
5. 到 `https://open.alipay.com/module/webApp` 创建应用
6. 拿到 `AppId`
7. 生成 RSA 密钥对
8. 上传应用公钥，拿到支付宝公钥
9. 把 `AppId`、应用私钥、支付宝公钥填进 `new-api`
10. 先联调，再正式上线

### 9.2 微信支付最短清单

1. 准备企业或个体工商户主体资料
2. 确保 PC 网站已备案并可公网访问
3. 在微信支付接入指引中申请普通商户号
4. 等待审核并在线签约
5. 收到商户号邮件
6. 注册或确认已有 `AppID`
7. 绑定 `mchid` 和 `AppID`
8. 申请商户 API 证书并保存私钥
9. 设置 APIv3 Key，下载平台证书
10. 把这些参数填进 `new-api` 后联调

## 12. 最后给你的建议

如果你准备的是正式生产环境，最推荐的推进顺序是：

1. 先把支付宝和微信都按“单商户自营直连”思路申请下来
2. 先完成沙箱 / 小额联调，不要直接上线
3. 先确认回调成功、查单成功、幂等成功
4. 最后再把静态码入口下掉，切到正式官方接口

这样做的好处是：

- 改造风险最低
- 财务和运营压力最小
- 后续最容易继续扩展退款、对账、异常单处理
