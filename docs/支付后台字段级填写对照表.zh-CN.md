## 1. 这份表是干什么的

这份文档不讲抽象概念，只回答一个问题：

> 后台支付设置页里的每个字段，到底应该填什么、从哪里拿、填错会怎样。

适合这几类人直接照着填：

- 第一次接支付宝 / 微信官方支付

- 后台字段太多，不知道哪些必须填、哪些可留空

## 3. 最先填、必须先对的字段

如果你只想知道“先填什么”，顺序就是这 4 步：

1. 先填 `ServerAddress`
2. 再填官方支付参数或 `epay` 参数
3. 再开对应开关
4. 最后再调 `PayMethods` 和前台显示

原因很简单：

- `ServerAddress` 不对，回调地址大概率就不对
- 参数没填全，开关会开不起来
- 开关没开，前端不会显示支付入口
- 入口显示了，也不代表回调就通了

## 4. 通用设置字段对照表

### 4.1 `ServerAddress`

| 项 | 说明 |
| --- | --- |
| 后台键名 | `ServerAddress` |
| 页面位置 | `通用设置` |
| 作用 | 作为站点正式访问地址，也会参与拼接支付回调地址 |
| 应该填什么 | 你的正式 HTTPS 域名，例如 `https://pay.example.com` |
| 从哪里拿 | 你自己已经备案并上线的业务域名 |
| 是否必填 | 是，官方支付尤其必须先填 |
| 常见错误 | 填成 `http://localhost:3000`、`http://127.0.0.1:3000`、前端开发地址、内网地址 |
| 错误后果 | 回调地址错误、按钮不开、支付成功但不入账 |

补充说明：

- 当前官方支付设置页在提交前会先检查 `ServerAddress`
- 支付宝回调默认拼成：`{ServerAddress}/api/alipay/notify`
- 微信回调默认拼成：`{ServerAddress}/api/wechatpay/notify`

## 5. 旧 `epay` / 聚合支付字段对照表

这部分只在你还需要兼容 `ZPAY`、其他 `epay` 平台，或者保留旧通道时才填写。

### 5.1 `PayAddress`

| 项 | 说明 |
| --- | --- |
| 后台键名 | `PayAddress` |
| 页面位置 | `支付设置` |
| 作用 | 第三方 `epay` 网关地址基址 |
| 应该填什么 | 真实的第三方网关域名，例如 `https://zpayz.cn` |
| 从哪里拿 | 你签约的聚合支付平台文档 |
| 是否必填 | 只对旧 `epay` 通道必填 |
| 常见错误 | 填成自己前端地址、填成收款码图片地址、填成 `submit.php` 完整页面地址 |
| 错误后果 | 跳错页面、打开本地 `submit.php`、支付请求失败 |

提醒：

- 这里不是填你的站点地址
- 这里也不是填“支付宝收款码链接”
- 当前旧链路里，前端会把表单提交到这个网关生成的支付入口

| --- | --- |

| 页面位置 | `支付设置` |

| 从哪里拿 | 聚合支付平台商户后台 |
| 是否必填 | 对旧 `epay` 通道必填 |
| 常见错误 | 填成支付宝 `AppId`、微信商户号、用户编号 |
| 错误后果 | 下单签名错、平台提示商户不存在 |

### 5.3 `EpayKey`

| 项 | 说明 |

| 从哪里拿 | 聚合支付平台商户后台 |
| 是否必填 | 对旧 `epay` 通道必填 |
| 常见错误 | 填成登录密码、填错环境、复制时多空格 |

### 5.4 `CustomCallbackAddress`

| 项 | 说明 |
| --- | --- |
| 后台键名 | `CustomCallbackAddress` |
| 页面位置 | `支付设置` |
| 作用 | 覆盖默认回调基础地址 |
| 应该填什么 | 一个可公网访问、专门用于支付回调的 HTTPS 地址 |
| 从哪里拿 | 你的反向代理 / API 域名设计 |
| 是否必填 | 否 |
| 不填时 | 默认使用 `ServerAddress` |
| 常见错误 | 填成前端域名、填成不带 HTTPS 的测试地址、填成内网地址 |
| 错误后果 | `epay` 回调打不到、旧订单不到账 |

项目里的回调基础地址选择逻辑在：

- `service/epay.go`

逻辑是：

- 有 `CustomCallbackAddress` 就优先用它
- 没填就用 `ServerAddress`

### 5.5 `PayMethods`

| 项 | 说明 |
| --- | --- |
| 后台键名 | `PayMethods` |
| 页面位置 | `支付设置` |
| 作用 | 控制钱包页显示哪些旧支付方式 |
| 格式 | JSON 数组 |
| 常见值 | `alipay`、`wxpay` |
| 是否必填 | 旧 `epay` 模式建议填；纯官方模式可以清理旧值 |

示例：

```json
[
  {
    "name": "支付宝",
    "color": "rgba(var(--semi-blue-5), 1)",
    "type": "alipay"
  },
  {
    "name": "微信",
    "color": "rgba(var(--semi-green-5), 1)",
    "type": "wxpay"
  }
]
```

常见错误：

- JSON 格式错
- 明明已经改成人工充值或官方直连，却还保留 `alipay` / `wxpay`

错误后果：

- 钱包页继续出现旧 `submit.php` 在线支付入口

| 从哪里拿 | 微信支付商户平台下载的平台证书 |
| 是否必填 | 是 |
| 常见错误 | 填成商户证书、证书过期未更新 |
| 错误后果 | 回调验签失败 |

---

## 9. 不同模式下，哪些字段该填、哪些该清

### 9.1 只用 `ZPAY` / `epay`

建议这样：

- 必填：`ServerAddress`、`PayAddress`、`EpayId`、`EpayKey`
- 选填：`CustomCallbackAddress`、`PayMethods`
- 关闭：`AlipayOfficialEnabled`、`WeChatPayOfficialEnabled`

### 9.2 只用官方直连

建议这样：

- 必填：`ServerAddress` + 官方支付所有必填参数
- 关闭：旧 `epay` 开关和旧 `PayMethods` 里的 `alipay` / `wxpay`
- 如不用人工充值：关闭 `ManualTopUpEnabled`

### 9.3 官方直连 + `ZPAY` 并行

这是迁移期最推荐的方式：

- 保留：`PayAddress`、`EpayId`、`EpayKey`
- 新增：官方支付所有必填参数
- 打开：`AlipayOfficialEnabled`、`WeChatPayOfficialEnabled`
- 保留：旧通道作为回退

### 9.4 只用人工收款码

建议这样：

- 打开：`ManualTopUpEnabled`
- 填：个人支付宝 / 微信收款码图片 URL
- 清理：旧 `PayMethods` 里的 `alipay` / `wxpay`
- 留空：`PayAddress`、`EpayId`、`EpayKey`

## 10. 填完后，立刻怎么自查

填完后台后，不要直接以为已经好了。至少按这个顺序自查：

1. 看钱包页有没有出现正确的支付按钮
2. 点支付宝官方，能不能生成二维码
3. 点微信官方，能不能生成二维码
4. 用真实小额支付，看是否自动到账
5. 再看一眼回调日志和订单状态

关键接口路径：

- 支付宝官方下单：`/api/user/alipay/pay`
- 微信官方下单：`/api/user/wechat/pay`
- 旧 `epay` 下单：`/api/user/pay`
- 人工充值：`/api/user/manual/pay`
- 订单状态轮询：`/api/user/topup/status/:tradeNo`
- 支付宝回调：`/api/alipay/notify`
- 微信回调：`/api/wechatpay/notify`
- 旧 `epay` 回调：`/api/user/epay/notify`

## 11. 最容易填混的 6 组字段

### 11.1 `ServerAddress` 和 `PayAddress`

- `ServerAddress` 是你自己的站点地址
- `PayAddress` 是第三方 `epay` 网关地址

### 11.2 `EpayId` 和 `WeChatPayOfficialMchId`

- `EpayId` 是第三方平台商户号
- `WeChatPayOfficialMchId` 是微信官方商户号

### 11.3 `AlipayOfficialAppId` 和 `EpayId`

- `AlipayOfficialAppId` 是支付宝开放平台应用 ID
- `EpayId` 是聚合平台商户 ID

### 11.4 `WeChatPayOfficialSerialNo` 和 `WeChatPayOfficialPlatformCert`

- `SerialNo` 是证书序列号
- `PlatformCert` 是平台证书 PEM 内容

### 11.5 `ManualTopUpAlipayQRCode` 和 `PayAddress`

- 前者是图片 URL
- 后者是支付网关地址

### 11.6 `PayMethods` 和官方支付开关

- `PayMethods` 决定旧 `epay` 入口显不显示
- 官方支付开关决定官方支付能力是否启用

它们不是同一个东西。

## 12. 一句话建议

如果你现在最怕“字段填错导致全站收款异常”，最稳的方式是：

> 先只改 `ServerAddress` 和官方参数，不删旧 `ZPAY` 配置；等官方真实支付和真实回调都跑通后，再清理旧字段和旧按钮。
