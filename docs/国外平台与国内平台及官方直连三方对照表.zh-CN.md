# 国外平台与国内平台及官方直连三方对照表

更新时间：2026-04-20

## 1. 这份文档解决什么问题

这份文档把你前面会话里提到过的三类路线，放到一张统一视角里做对照：

- 国外 / 国际支付平台
- 国内聚合支付平台
- 支付宝 / 微信官方直连

它适合解决这几个问题：

- 我到底该看国外平台、国内平台，还是直接官方直连
- 这些平台之间的差异主要体现在哪
- 哪些适合当前 `new-api` 项目，哪些只是扩展视野
- 我现在做国内充值、以后做国际支付时，应该怎么拆主链路和备用链路

---

## 2. 先给一句总判断

如果把之前所有讨论压成一句话，就是：

> 国内充值场景下，当前 `new-api` 最现实的是“国内聚合平台或官方直连”；国际出海场景下，更应该看 `Stripe`、`Adyen`、`Checkout.com`、`Airwallex`、`dLocal`、`Paddle` 这类国际平台；而官方直连则更适合作为中国大陆长期主链路。

---

## 3. 三类路线到底各自是什么

## 3.1 国外 / 国际支付平台

这里主要指你前面会话里提到和推荐过的国际平台，例如：

- `Stripe`
- `Adyen`
- `Checkout.com`
- `Airwallex`
- `dLocal`
- `Paddle`
- `PayPal / Braintree`
- `Worldpay`

它们更偏：

- 国际卡支付
- 海外本地支付方式
- 订阅
- 平台分账
- 多币种
- 出海业务

## 3.2 国内聚合支付平台

这里主要指：

- 兼容 `epay / 易支付` 协议的一类平台
- 以及会话里提到过的国内支付服务商 / 聚合服务商 / 收单平台，例如：
  - `ZPAY`
  - `Ping++`
  - `PayJS`
  - `汇付天下`
  - `富友`
  - `拉卡拉`

它们更偏：

- 国内网站充值
- 支付宝 / 微信扫码
- 收单
- 平台支付
- 行业支付方案

## 3.3 官方直连

这里指：

- 支付宝官方直连
- 微信支付官方直连

它更偏：

- 中国大陆正式商户能力
- 官方接口
- 更短支付链路
- 更高长期可控性

---

## 4. 三方对比总表

| 对比维度 | 国外 / 国际平台 | 国内聚合平台 | 官方直连 |
| --- | --- | --- | --- |
| 典型代表 | `Stripe`、`Adyen`、`Checkout.com`、`Airwallex`、`dLocal`、`Paddle` | `ZPAY`、`Ping++`、`PayJS`、`汇付天下`、`富友`、`拉卡拉` | 支付宝官方、微信支付官方 |
| 主战场 | 国际收款、出海、订阅、卡支付 | 国内支付宝/微信聚合收款、行业支付、网站扫码 | 中国大陆官方支付链路 |
| 适合币种 | 多币种 | 主要人民币 | 主要人民币 |
| 适合支付方式 | 国际卡、本地 APM、订阅、平台分账 | 支付宝、微信、部分银行卡、行业方案 | 支付宝官方、微信官方 |
| 项目接入门槛 | 中到高，受主体和国家影响 | 中，很多平台强调快速接入 | 高，需要正式商户能力与密钥证书 |
| 对 `new-api` 旧链路兼容性 | 低到中 | 高，尤其 `epay` 类平台 | 中，需走项目里的官方支付分支 |
| 上线速度 | 国际场景快，但受开户主体限制 | 国内场景快 | 相对慢 |
| 前端体验 | 常见是 Checkout / Hosted Page / 卡支付页 | 常见跳第三方收银台或聚合页面 | 常见直接出本站二维码弹窗 |
| 成本透明度 | 差异大，国际平台通常较透明 | 差异大，很多需要商务确认 | 通常更透明 |
| 长期可控性 | 高于国内小聚合平台，但受平台政策约束 | 相对较弱 | 最强 |
| 是否适合当前国内充值主链路 | 不适合 | 适合过渡或备用 | 最适合长期主链路 |

## 5. 如果按“你现在做什么业务”来选

## 5.1 你现在主要做国内网站充值

更适合优先看：

1. 支付宝 / 微信官方直连
2. 国内聚合平台（尤其 `epay` 兼容平台）

这时通常不优先看国际平台，原因很简单：

- 国际平台主要解决的是国际卡、本地支付方式、出海结算问题
- 你当前重点是国内支付宝 / 微信扫码充值

## 5.2 你现在主要做海外开发者收款 / 出海 SaaS

更适合优先看：

1. `Stripe`
2. `Paddle`
3. `Adyen`
4. `Checkout.com`

这里国内聚合平台通常不是主选，因为它们解决的不是国际主体、国际卡、订阅、税务合规问题。

## 5.3 你未来想同时做国内和海外

更合理的结构是：

- 国内：支付宝 / 微信官方直连为主
- 国内备用：国内聚合平台
- 海外：国际平台单独走一套

也就是说，很多时候不是“三选一”，而是：

> 不同市场用不同主链路

---

## 6. 国外平台这边，当时主要怎么推荐

## 6.1 `Stripe`

当时基本属于国际路线里的默认主推荐。

适合：

- 出海 SaaS
- API 平台
- 海外开发者产品
- 订阅和充值

特点：

- API 和文档强
- Checkout、Billing、Connect 很成熟

## 6.2 `Adyen`

更偏企业级和全渠道。

适合：

- 大中型企业
- 多国家
- 线上线下一体化

## 6.3 `Checkout.com`

更偏中大型国际线上业务强备选。

适合：

- 跨境电商
- 大中型线上收款

## 6.4 `Airwallex`

更偏跨境支付加资金管理。

适合：

- 跨境品牌
- 多币种
- 强资金流需求

## 6.5 `dLocal`

更偏新兴市场支付方式覆盖。

适合：

- 拉美
- 中东
- 非洲
- 新兴市场本地支付

## 6.6 `Paddle`

更偏订阅、数字产品、SaaS，并且适合不想自己扛太多税务和法定销售主体责任的团队。

## 6.7 `PayPal / Braintree`

更适合作为补充支付方式，用来提高欧美钱包支付转化。

---

## 7. 国内平台这边，当时主要怎么推荐

## 7.1 `epay / 易支付` 兼容平台

这是当时对 `new-api` 国内旧链路最贴近的一类平台。

适合：

- 先上线
- 先少改代码
- 保留旧支付逻辑

## 7.2 `ZPAY`

它不是一开始就被当作唯一推荐，而是后来通过真实链路分析确认：

- `ikuncode` 实际用的就是它

所以它在讨论里的位置是：

- `epay` 类平台的一个真实具体实例

## 7.3 `Ping++`

更偏开发者型 / 平台型聚合支付服务商。

适合：

- 统一 API
- 平台化支付能力
- 统一支付层设计

## 7.4 `PayJS`

更偏国内聚合收款平台示例。

## 7.5 `汇付天下`

更偏平台业务、清结算、分账、行业方案。

## 7.6 `富友` / `拉卡拉`

更偏：

- 收单
- 门店
- 行业支付
- 传统支付服务商 / 聚合服务商视角

它们在之前会话里更多是“市场玩家示例”，不是针对你当前 `new-api` 项目做的首选主推。

---

## 8. 官方直连为什么在这张表里单独列出来

因为前面的推荐一直都不是在说：

- 聚合平台一定比官方好

而是在说：

- 聚合平台更适合某个阶段
- 官方直连更适合某个阶段

对于当前 `new-api` 项目，官方直连单独列出来有两个原因：

### 原因一：它是长期最重要的对照路线

因为对中国大陆支付来说，真正长期最稳的主链路通常还是：

- 支付宝官方
- 微信官方

### 原因二：它是当前项目已经有实现基础的路线

当前项目里已经有：

- 支付宝官方扫码
- 微信 Native 官方扫码

所以它不是遥远方案，而是已经进入当前项目实际能力范围内的路线。

---

## 9. 如果只看“对当前项目是否适合”，怎么排优先级

对你当前这个 `new-api` 项目来说，更现实的优先级通常是：

## 9.1 国内主链路

1. 官方直连
2. 国内 `epay` 聚合平台作为过渡或备用

## 9.2 国际主链路

1. `Stripe`
2. `Paddle`（如果你更偏订阅和税务合规托管）
3. `Adyen` / `Checkout.com`（如果你规模更大、更企业级）

## 9.3 不建议的做法

不建议：

- 用国内聚合平台去硬扛国际收款主链路
- 用国际卡支付平台去替代国内支付宝 / 微信官方长期主链路

因为这两类平台解决的问题本来就不同。

---

## 10. 三方路线各自最适合什么阶段

| 阶段 | 更适合的路线 | 说明 |
| --- | --- | --- |
| 国内项目起步 | 国内聚合平台 | 快落地、少改代码 |
| 国内项目稳定后 | 官方直连 | 更适合长期生产 |
| 海外出海起步 | `Stripe` / `Paddle` | 取决于你偏支付控制权还是偏合规托管 |
| 国际业务做大后 | `Adyen` / `Checkout.com` / `Airwallex` 等强备选 | 适合更复杂、更多国家和企业级需求 |

---

## 11. 如果把之前的推荐压成一句“选型口诀”

可以压成下面这句：

> 国内充值先看“官方直连 + 国内聚合备用”，国际收款先看 `Stripe`，订阅合规先看 `Paddle`，企业级全球化再看 `Adyen` / `Checkout.com` / `Airwallex`，新兴市场再补 `dLocal`。
